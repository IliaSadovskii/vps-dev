# Возможности Agent of Empires, которые касаются оркестрации

Сверено 2026-09-05 с установленной версией `aoe 1.15.2` и исходниками
`github.com/agent-of-empires/agent-of-empires` (клон `/tmp/aoe-src`,
документация в `docs/`, серверные маршруты в `src/server/router.rs`,
API плагинов в `src/plugin/host_api.rs` и `src/plugin/session_api.rs`).
На этой машине: демон `aoe serve` на `127.0.0.1:8065` с `--auth none`,
адаптеры `claude-agent-acp 0.73.0`, `codex-acp 1.8.0`, `opencode` нативно,
Node 22. `aoe acp doctor` зелёный для claude, codex, opencode.

Каждый пункт помечен: **есть** — проверено в коде или руками;
**есть, не проверено** — есть в коде, руками не гонял; **нет** — придётся
делать самим.

## Сессии

- **есть** Сессия = один агент (claude / codex / opencode) в одном каталоге,
  со своей моделью, усилием (`effort`) и режимом разрешений
  (`default` / `acceptEdits` / `bypassPermissions` / `plan`). Структурный
  режим (ACP) даёт нативный рендер: план, карточки инструментов, диффы,
  вопросы, одобрения. Терминальный режим (tmux) нам не нужен.
- **есть** Сессия переживает перезапуск демона и машины: воркер отделён
  от демона, транскрипт в SQLite, у Claude восстанавливается и контекст
  модели (`docs/development/internals/structured-view.md`).
- **есть** Очередь промптов на сервере: промпт в идущий ход у Claude
  подмешивается («steered»), у остальных ставится в очередь и уходит на
  границе хода; промпт в уснувшую сессию её будит. Ответ
  `POST /acp/prompt` говорит, что произошло: `sent | steered | queued`.
- **есть** Форк сессии (`fork_from`): новая сессия с тем же контекстом
  разговора, дальше расходятся. Только Claude. Это готовый механизм
  «передать контекст следующему агенту без файлов».
- **есть** Смена агента внутри сессии (`switch-agent`): транскрипт
  остаётся, модель другого вендора стартует с нуля плюс авто-пересказ
  последних 20 ходов (`context-primer`, ~24k символов, в композер, не
  отправляется само). Пригодится при лимитах.
- **есть** Смена модели и усилия внутри живой сессии
  (`POST /acp/config-option`, `POST /acp/mode`).
- **есть** Титул, группа, цвет (`red|amber|green`), закрепление, архив,
  снуз, корзина, флаг «непрочитано», флаг «срочно» (файл
  `/tmp/aoe-hooks-<uid>/<id>/attention.json`, читается в сортировку
  «Attention»).
- **есть** `AOE_ARTIFACT_DIR` на сессию: файлы оттуда открываются из
  транскрипта по ссылке, картинки рендерятся. Каталог на сессию, не на
  задачу.
- **есть** Умное переименование по первому ходу — только пока титул
  автосгенерирован; заданный нами титул не трогает.
- **есть, не проверено** `bypassPermissions` для Claude документация
  привязывает к `ALLOW_BYPASS=1` в окружении демона; у нашего демона
  переменной нет, а текущая сессия работает без одобрений. Вероятно,
  снято в новых версиях адаптера. Проверить в первом спайке.

## HTTP API (`docs/api.md` + `src/server/router.rs`)

Без токена на loopback, поскольку демон запущен с `--auth none`.

| Что | Маршрут |
|---|---|
| Список сессий со статусом `Starting/Running/Waiting/Idle/Error/Stopped` | `GET /api/sessions?state=live` |
| Создать сессию | `POST /api/sessions` — `path`, `tool`, `title`, `group`, `view: structured`, `agent_name`, `agent_model`, `agent_effort`, `yolo_mode`, `extra_env`, `worktree_enabled`, `worktree_branch`, `create_new_branch`, `base_branch`, `extra_repo_paths`, `fork_from`, `idempotency_key`, `callback_url`, `trust_hooks`, `?wait=ready` |
| Промпт | `POST /api/sessions/{id}/acp/prompt` → `{disposition}` |
| Комментарии к диффу как промпт | `POST /api/sessions/{id}/acp/prompt/diff-comments` |
| Отмена хода / принудительное завершение | `POST .../acp/cancel`, `.../acp/force_end_turn` |
| Ответить на одобрение / на вопрос агента | `POST .../acp/approvals/{nonce}`, `.../acp/elicitations/{nonce}` |
| Транскрипт (строки для UI или сырые события, постранично) | `GET .../acp/replay?view=rows&before=&limit=` |
| Живой поток событий | `WS /sessions/{id}/acp/ws`; из CLI `aoe acp tail <id>` (JSON по строке) |
| Сменить режим / модель / усилие | `POST .../acp/mode`, `.../acp/config-option` |
| Переименовать, группа, цвет, закрепить, архив, снуз, корзина, восстановить | `PATCH /api/sessions/{id}`, `.../group`, `.../color`, `.../pin`, `.../trash`, `.../restore` |
| Остановить / запустить воркер | `POST .../stop`, `.../start`, `.../acp/spawn`, `DELETE .../acp` |
| Краткий пересказ разговора одноразовой моделью | `POST .../summarize` |
| Файл из рабочей копии сессии, дифф | `GET .../file`, `.../diff/file` |
| Список групп, проекты, агенты и каталог моделей | `GET /api/groups`, `/api/projects`, `/api/acp/agents`, `/api/acp/option-catalog` |

Оговорки:

- `callback_url` (POST при переходе в `Waiting/Idle/Error`) **отвергает
  loopback и частные адреса** — для локального оркестратора бесполезен.
  Конец хода ловить по WS: событие `Stopped`; вопрос агента —
  `ElicitationRequested`; запрос разрешения — `ApprovalRequested`.
- Статус структурной сессии выводится из ACP-событий: `Stopped` → `Idle`,
  `ElicitationRequested`/`ApprovalRequested` → `Waiting`
  (`src/server/acp_events.rs`).
- `[status_hooks]` (команды на смену статуса) выполняет только TUI, не
  демон. Для нас не канал.

## Плагины (`docs/plugin-api.md`, `api_version 13`)

Плагин = каталог с `aoe-plugin.toml` и воркером на любом языке: JSON-RPC
2.0 по stdio, одна строка — одно сообщение. Воркер живёт пока живёт
`aoe serve`, перезапускается при падении (не больше 3 раз в минуту),
stderr в `~/.config/agent-of-empires/plugin-workers/`.

Что воркер может:

- **UI-слоты** (рендерит хост, код плагина в браузер не попадает):
  `home-pane` — глобальная док-панель на обзоре и поверх структурного
  вида; `pane` — док-панель внутри сессии; `row-badge`, `row-column`,
  `detail-badge` — на строке сессии в сайдбаре; `sort-key`, `filter-facet`;
  `composer-action` — кнопка рядом с полем ввода; `status-bar`, `card`.
  Обновление через `ui.state.set`, payload до 64 КиБ.
- **Блоки панели**: `heading`, `note`, `divider`, `row` (две строки,
  бейджи, кликабельная с `method`+`params`), `section` (сворачиваемая,
  прокручиваемая), `callout` (карточка-вердикт с кнопками), `bar`,
  `sparkline`, `columns`, `action` (кнопка → метод воркера, `primary`,
  `disabled`), `comment`. Клик приходит воркеру как уведомление
  `{method, params, session_id}` — хост сам подставляет `session_id`,
  подделать нельзя. TUI рисует панели только для чтения.
- **`composer-action` + `composer.read`**: кнопка получает текущий текст
  из поля ввода сессии. Это единственный способ получить от человека
  свободный текст без участия модели. `composer.write` может заменить или
  очистить черновик.
- **Уведомления** `ui.notify` (в браузер), пуш-уведомления на телефон
  идут отдельно по статусам (`Waiting`, `Idle`, `Error`, одобрение,
  вопрос).
- **`sessions.list`**, **`session.meta.get/set/cas`** (свои метаданные на
  сессии, переживают удаление плагина), **`plugin.storage.*`** (64 ключа
  по 64 КиБ — для задач мало, для настроек хватит), **`config.get`** +
  уведомление `plugin.settings.changed`, **`events.publish/subscribe`**
  (шина только между плагинами; хост в неё ничего не публикует).
- **Настройки** с виджетами: `dynamic_select` по агентам/моделям/режимам/
  проектам/группам, `object_list`, `cron`, `multiline`. Рендерятся в TUI и
  веб.
- **Команды** в палитре (`plugin.<id>.<cmd>`), горячие клавиши.
- **`sessions.create` / `sessions.turn.send`** — есть, но с лимитами
  **5 активных сессий, 20 созданий в час, 120 ходов в час** на плагин и
  только к своим сессиям. Для цепочки из 17 шагов не годится; сессии
  создавать через HTTP API, где лимитов нет.
- Хост **не** сообщает плагину о смене статуса сессии или конце хода.
  Узнавать через WS или опрос `sessions.list`/`GET /api/sessions`.

Эталонный плагин автоматизации — `agent-of-empires/plugin-cron`
(Rust, `object_list` задач, `sessions.create` с `initial_turn`).
Шаблон: `cookiecutter gh:agent-of-empires/plugin-template` (Python / Node /
Rust).

## MCP для агентов (`docs/guides/mcp-servers.md`)

- **есть** `~/.config/agent-of-empires/mcp.json` (и на профиль, и
  доверенный `.mcp.json` проекта) пробрасывается структурным сессиям
  Claude, Codex, Gemini при `session/new` и `session/load`. stdio-сервер
  запускает сам агент.
- **нет** Переменных окружения на одну сессию для обычных (не в песочнице)
  сессий: `extra_env` из `POST /api/sessions` попадает только в
  `sandbox_info` (`src/session/builder.rs:795`), общий список
  `environment` — на профиль. Идентифицировать задачу через окружение
  нельзя; идентифицируем по рабочей копии.
- **есть** Процесс агента получает `AOE_SESSION_ID`, `AOE_PROJECT_PATH`,
  `AOE_TOOL`, `AOE_PROFILE`, `AOE_AGENT_MODEL`, `AOE_ARTIFACT_DIR`
  (`src/acp/acp_client/spawn.rs`). `AOE_TOKEN` не пробрасывается.
- **есть, не проверено** Что stdio-MCP-сервер, запущенный адаптером,
  наследует эти переменные (Claude Code наследует окружение процесса при
  запуске MCP; для `codex-acp` проверить). От этого зависит, узнает ли
  наш MCP-сервер, какая сессия его вызвала.

## Рабочие копии и группировка

- **есть** Worktree на сессию: новая ветка от базовой или **подключение к
  существующей ветке** — тогда переиспользуется уже существующий каталог
  worktree (`create_new_branch: false`). Так несколько сессий одной задачи
  работают в одном каталоге. Мульти-репо (`extra_repo_paths`).
- **есть** Группы `group_path`; ось сайдбара «по репо», «по группе»,
  «репо и группа»; заголовок группы со счётчиком, сворачивается.
  Вложенные пути (`a/b`) в вебе показываются одной строкой, не деревом.
- **нет** Иерархии сессий в UI: `parent_session_id` в модели есть (флаг
  `--parent` в `aoe add`), но веб его не рисует.
- **есть** Хуки репозитория `.agent-of-empires/config.toml`:
  `on_create`, `on_launch`, `on_destroy` с `AOE_SESSION_ID`,
  `AOE_SESSION_TITLE`, `AOE_PROJECT_PATH`, `AOE_SESSION_BRANCH`.
  Требуют доверия к репо (`trust_hooks: true` в API).
- **есть** Песочница Docker на сессию (`sandbox: true`), при желании.

## Взаимодействие с человеком

- **есть** `AskUserQuestion` Claude → форма в вебе (радио/чекбоксы/
  «Другое»), ответ ложится в транскрипт как ход человека, пуш на телефон.
  В TUI — только одиночный выбор. Для Codex вопрос как форму адаптер не
  даёт (не проверено), нужен свой инструмент.
- **есть** Пуш-уведомления PWA по `Waiting`/`Idle`/`Error`/одобрению/
  вопросу, с настройкой на сессию (`notify_on_*`). Уже включено
  (`web.notify_on_waiting = true`).
- **есть** Диалог с агентом с телефона: композер, вложения, очередь
  промптов, Stop / Force stop.
- **есть** Комментарии на диффе, отправляемые агенту одним промптом
  (`prompt/diff-comments`) — готовый канал для Human Review.
- **нет** Канбан-доски, колонок, перетаскивания карточек. Нет и
  «ограниченных переходов» — нечего ограничивать. Всё это — наша панель.

## Профили и мультипровайдерность

- **есть** `acp.acp_defaults.<agent>` — модель, усилие, режим по умолчанию
  на агента; `effort_by_model`. Мы задаём всё явно на сессию через API,
  дефолты не нужны.
- **есть** Каталог моделей и режимов, который агент объявил
  (`acp_option_catalog.json`): у codex сейчас `gpt-5.6-sol/terra/luna`,
  `gpt-5.5`, `gpt-5.4-mini`, усилия low..; у claude — модели и усилия по
  `ConfigOptionUpdate`.
- `aoe-agent` (встроенный мультипровайдерный агент на Vercel AI SDK)
  работает по API-ключам, не по подпискам — нам не подходит.
