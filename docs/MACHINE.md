# Что проект должен знать про эту машину

Проект в `/projects` поднимает себя сам — как у него принято. Здесь только то,
чего он не может узнать из собственного репозитория: правила общежития на
конкретном сервере. Всё остальное (какие цели у Makefile, где тесты, как
устроен entrypoint) — дело проекта.

## Порты

Каждому проекту — блок из 10 портов. Узнать свой, а заодно забронировать,
если блока ещё нет:

```bash
ports claim <имя-проекта>   # вернёт блок, напр. 8010-8019; повторный вызов безопасен
ports map                   # карта: занято, зарезервировано, свободно
```

Реестр общий (`/var/lib/vps-dev/ports/`), правится только этой командой.
Занятость считается по реестру **и** по реально слушающим портам, поэтому
подобранный «на глаз» порт однажды столкнётся с соседом.

Не занимать: `8000-8009` (системное), `8060-8079` (службы машины),
весь `90xx` (зеркало под прокси).

**Публиковать только на loopback** — иначе сервис не попадёт ни в частную сеть,
ни на дашборд: их рисует `ports-web` по портам, которые docker опубликовал
на `127.0.0.1`.

```yaml
ports:
  - "127.0.0.1:${APP_PORT:-8010}:8000"
```

Дальше всё само: сервис появляется в tailnet **на том же номере порта**
и ссылкой на дашборде (`https://<машина>.<сеть>.ts.net/`).

Название карточки на дашборде — комментарий после порта в реестре;
без него будет угаданное из имени переменной:

```bash
APP_PORT=8010   # Приложение
```

Порт из блока стоит тратить только на то, к чему ходишь с хоста; остальное
общается внутри docker-сети и наружу не публикуется. Базы наружу не отдаются
никогда: `postgres`, `mysql`, `mariadb`, `mongo`, `redis`, `valkey` определяются
по образу и остаются внутри машины.

## Прокси перед веб-сервисами

Веб-порт машина отдаёт через общий Caddy: он сжимает ответы и ставит годовой
кэш статике **с отпечатком в имени** — `app-C6yGb0eL.css` внутри `build/`,
`assets/`, `static/` или `dist/`. Делать для этого ничего не надо, но следствие
учитывай: файл со стабильным именем в папке сборки браузер после правки не
перечитает — пусть сборщик проставляет хэш. Пришёл ли ответ через прокси,
видно по заголовку `X-Vps-Proxy`.

## Почта

На машине стоит ловушка Mailpit, наружу письма не уходят никогда. В `.env`
проекта — `MAIL_HOST=host.docker.internal`, `MAIL_PORT=1025`, без логина и TLS,
а в compose у сервиса, который шлёт письма:

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

Читать письма — на дашборде, порт 8069.

## Общежитие

- **На хост ничего не ставить** (`sudo apt install`, `npm -g`) — только контейнер.
- **`restart: unless-stopped`** у постоянных сервисов: машина перезагружается
  после обновлений ядра, и без политики проект после этого лежит. Именно
  `unless-stopped`, а не `always` — иначе остановленное намеренно поднимется само.
- **Память общая.** Сервис, который сегодня не нужен, лучше убрать из автозапуска
  (в docker — `profiles`), чем держать впустую.
- **Секреты — в `.env`**, в git только `.env.example`.
- **Файлы, которые контейнер пишет в смонтированный код** (`vendor/`,
  `node_modules/`, логи), должны принадлежать пользователю хоста, а не root —
  иначе после первого же запуска их не отредактировать. В docker это build-arg
  с UID/GID и `USER` в Dockerfile.
