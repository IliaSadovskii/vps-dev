## Кто трогал тесты — проверяется по истории, не по словам

Файлы тестов в истории задачи меняются только коммитами с трейлером
`Orch-Step: tests`. Реализация коммитит тесты первыми под этим трейлером, а
код — под своим; правка теста в любом другом коммите — блокирующая находка для
того, кто её нашла: назвать, довести до владельца, никогда не чинить правкой,
переносом, удалением теста или переписыванием истории.

Скрипт запускают Реализация (в конце хода) и Ревью кода (каждый заход) и
вставляют его вывод дословно в свой файл. Входы: стартовый коммит задачи из
блока задачи и шаблоны файлов тестов из `scoping.md#Тесты и проверки`, через
пробел.

```sh
START=<стартовый коммит> PATTERNS='<glob> <glob>' sh <<'EOF'
set -fu
: "${START:?стартовый коммит}"
: "${PATTERNS:?шаблоны файлов тестов}"
g() { git -C "${REPO:-.}" "$@"; }
status=0
for c in $(g rev-list --reverse "$START..HEAD"); do
  step=$(g show -s --format=%B "$c" \
    | sed -n 's/^Orch-Step:[[:space:]]*//p' | tail -n 1)
  for f in $(g show --pretty=format: --name-only "$c"); do
    for p in $PATTERNS; do
      case "$f" in
        $p) if [ "$step" != "tests" ]; then
              printf '%s %s [%s]\n' "$c" "$f" "${step:-no trailer}"
              status=1
            fi
            break ;;
      esac
    done
  done
done
if [ "$status" -eq 0 ]; then echo "test ownership: ok"
else echo "test ownership: FAIL"; fi
exit "$status"
EOF
```

Каждая строка вывода — `<коммит> <файл> [<трейлер или no trailer>]`; код
возврата ненулевой, если такие есть. Нет шаблонов в `scoping.md` — проверка
невозможна, так и напиши, не угадывай. Нет самого `scoping.md` — это короткая
цепочка без разведки: определи шаблоны по раскладке тестов репозитория, назови
их в своём файле рядом с выводом скрипта и запусти проверку. Здесь угадывать не
из чего, а не проверять — хуже.
