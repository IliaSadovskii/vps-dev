# Решения, которые я принял сам

Что не решалось по документам. Формат: вопрос, варианты, взятый вариант и
почему. Все взяты по духу `PLAN.md`; отменить любое — правка на одну строку.

## 1. Плагин не виден живому демону без перезапуска

**Вопрос.** `aoe plugin install --yes ./orch` пишет плагин на диск, но реестр
плагинов в демоне — глобальный синглтон процесса
(`src/plugin/mod.rs:63`, `reload_registry` зовётся только изнутри
install/enable этого же процесса). Локальный путь `POST /api/plugins/install`
не принимает («web install supports gh: sources only»), а
`POST /api/plugins/{id}/enabled` отвергает id, которого нет в реестре демона.
Значит, впервые поставленный плагин оживает только при рестарте `aoe serve`, а
рестарт запрещён (`HANDOFF.md`) — он оборвёт и мою сессию.

**Варианты.**
1. Отдельный демон для разработки плагина: `XDG_CONFIG_HOME` и `XDG_DATA_HOME`
   в `/tmp/orch-spike`, `aoe serve --port 8199 --auth none`. Рабочий демон на
   8065 не трогается вовсе.
2. Просить владельца перезапустить демон.
3. Отложить весь этап 2 до утра.

**Взял 1.** Спайк 4 и разработка панели идут против демона на 8199; там же
плагин ставится и перезапускается сколько нужно. Рабочий демон не трогается.

**Что остаётся владельцу.** Один раз перезапустить `aoe serve` на 8065, чтобы
панель появилась в рабочем дашборде (это и есть «пройти smoke с телефона»,
критерий этапа 2). Команда: `aoe serve --restart`. После первого рестарта
плагин попадает в реестр демона, и дальше правки кода подхватываются
переключением `aoe plugin disable` / `enable` без рестарта.

## 2. Спайк 5: вопрос висит не два часа, а полчаса

**Вопрос.** `RISKS.md` просит проверить, что `AskUserQuestion` висит два часа
и ничего его не гасит. Два часа — это два часа ночной работы впустую.

**Варианты.**
1. Держать вопрос висящим фоном (десятки минут), пока идут остальные проверки,
   плюс доказательство из исходников, что таймера нет вовсе.
2. Честно ждать два часа.

**Взял 1.** В исходниках единственное, что гасит висящий вопрос, —
перезапуск демона: `cancel_orphaned_elicitations`
(`src/acp/supervisor.rs:3340`) публикует синтетический
`ElicitationResolved { outcome: Cancelled }` для нонсов, осиротевших после
смерти прежнего демона. Ни TTL, ни таймера, ни подметания по времени нет.
Два часа проверяют то же, что и полчаса, только дороже.

**Следствие для движка, не для спайка.** После рестарта демона висевший вопрос
снимается, ход роли заканчивается без сигнала — движок увидит `Idle` без
сигнала и остановит задачу с причиной «нет сигнала». Это уже описанное
поведение (`PLAN.md` §5 п. 4), отдельного кода не нужно.

## 3. Папка `logs/` в задаче

**Вопрос.** `prompts/common-protocol.md` велит ролям писать вывод команд в
`logs/<шаг>.txt` внутри папки задачи, а `PLAN.md` §3 такой папки не
перечисляет (там только `history/<step>-<n>/log.txt`).

**Взял:** движок создаёт `.orch/<task>/logs/` вместе с остальными папками и
называет путь в блоке задачи; при копии захода в `history/` логи копируются
туда же. Промпт менять не стал: роли уже написаны под `logs/`, а лишняя папка
дешевле, чем правка протокола.

## 4. Кнопка у поля ввода прикрепляет текст, а не двигает задачу

**Вопрос.** `PLAN.md` §8 описывает `composer-action` так: «читает черновик,
показывает варианты движения (`moves` + Принять), текст → `move.comment`».
Кнопка у поля ввода — одна кнопка, вариантов движения показать не может. А
кнопки панели, которые варианты показывают, черновика поля не видят: хост
прикладывает снимок композера только к клику по кнопке у поля
(`strip_composer_snapshot_without_capability`, `src/server/api/plugins.rs`).
Первая версия двигала задачу «принять» прямо по клику у поля — комментарий
доезжал, но выбрать возврат было нечем, и живой прогон это показал: возврат
кнопкой панели уехал без комментария.

**Варианты.**
1. Два шага: клик у поля прикрепляет текст к задаче и очищает поле, панель
   показывает «Комментарий к следующему движению: …» и кнопки движения;
   кнопка панели забирает прикреплённый текст в `move.comment`.
2. Держать в панели по кнопке на каждое движение и просить владельца писать
   комментарий только через кнопку у поля, которая всегда «принять».
3. Своё окно ввода в панели — запрещено (`PLAN.md` §12, ничего своего).

**Взял 1.** Ровно то, что описано в `PLAN.md`, только «показывает варианты
движения» делает панель задачи, а не сама кнопка: другого места для списка
вариантов в API плагинов нет. Побочно вышло безопаснее — случайный клик у
поля больше не двигает задачу, а только прикрепляет текст.

## 5. Адрес демона AoE стал настройкой плагина

**Вопрос.** `PLAN.md` §8 перечисляет четыре настройки плагина; адреса демона
среди них нет, он зашит как `127.0.0.1:8065`. Но панель разрабатывается на
запасном демоне на другом порту (п. 1), и воркер обязан ходить туда же, где
живёт сам, иначе создаёт сессии в чужом демоне.

**Взял:** пятая настройка `aoe_url` (по умолчанию `http://127.0.0.1:8065`,
помечена как «для опытных»), плюс переменная окружения `ORCH_AOE_URL` для
запуска движка руками. Порт демона — параметр развёртывания, а не константа
кода; в роли Ansible он и так задаётся.
