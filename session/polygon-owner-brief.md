# Полигон: что я как владелец отвечаю скиллам

Моя роль в ночном прогоне — владелец `single-session-crm`. Чтобы ответы были
одинаковыми во всех кругах, решения записаны заранее. Источник — `listate-crm/docs/`
и `wlist`; где я согласен с listate, беру его решение, где не нужно полигону —
режу.

## Продукт

CRM для агентства недвижимости: застройщики, комплексы, корпуса, лоты,
подборки для покупателей. Пользователи — брокеры и руководитель агентства;
партнёрская роль только смотрит. Приложение передаётся агентству снимком без
истории git, поэтому обязано работать само по себе.

Готово, когда: брокер входит, видит комплексы и лоты своего агентства, заводит
и правит лот, а то, что ему не положено по роли, не видит и не может сделать.

Не продукт: маркетплейс, биллинг и тарифы, мультиарендность (её надстроит
платформа снаружи), импорт и фиды площадок (позже), PDF-презентации (позже),
публичный каталог.

## Стек, «не брать»

Стек как в коде: Laravel, Inertia + Vue 3, OpenVue через свои обёртки, Pest,
PostgreSQL, Redis. Не брать: Filament; `JsonResource` (граница — `Data`);
EAV и таблицу «объект-атрибут-значение»; отдельный SPA; Elasticsearch;
RabbitMQ/Kafka; вторую палитру или UI-kit мимо обёрток `App*.vue`.

## Правила, которые держу (все из CRM-RULES, дешёвые сейчас)

- Одноарендность: никаких `tenant_id`, глобальных скоупов, явных соединений
  (`DB::connection`), `storage_path()`; файлы через `Storage::disk('tenant')`.
- Домен не знает про HTTP и консоль; контроллеры тонкие; проверка ввода в
  `Data`; значения с инвариантом — свои классы.
- UUID v7 у того, что уходит наружу (лот, комплекс, корпус, застройщик,
  подборка); роутинг по uuid; справочникам uuid не нужен.
- Миграции только в `database/migrations/tenant/`, только расширяющие.
- Enum в коде для того, на чём висит логика (статус лота, тип сделки);
  таблица для того, что клиент дополняет; ветвление только по системному коду
  или признаку записи, никогда по id.
- Роли и права — `spatie/laravel-permission`; роли сеются сидером, не
  миграцией; партнёрская роль системная, только просмотр; проверка в
  политике, кнопка в UI скрывается по той же политике.
- События домена — публичный контракт: имя, состав, место.
- Логика не в контроллерах; задачи очередей объявляют очередь по смыслу.

## Ловушки (уже ошибались)

- `lang/**/*.php` уезжает в публичный бандл фронта.
- `make:model` без полного пути кладёт класс в корень `App\`.
- OpenVue закреплён точной версией rc: семверный диапазон у rc непредсказуем.
- Пакет одноразовых кодов различает два исхода, но переводит их одинаково;
  разойдутся — дверь начнёт выдавать, заведён ли адрес.

## Проверки

Arch, Unit, Feature (настоящий PostgreSQL), Browser (Playwright) — есть; типы
100 %. Визуальные (раскладка) — отложено 2026-09. Контрактные для API —
отложено до появления `routes/api.php`. Проверки данных при миграции —
одобрено поставить, когда появится первая миграция с данными.

## Когда останавливаться

Схема БД; публичный контракт (API, событие домена, экспорт); новая
зависимость; необратимая миграция; красный тест после одного круга; тест,
утверждающий неверное; развилка, где проект решил по-разному.

## Git

PR до 400 строк диффа; коммиты по-русски; форма PR из пяти заголовков;
никогда: `reset --hard`, `checkout -- .`, `clean -fd`, `push --force`,
`git add .`; агент не сливает PR.

## Каркас — что скажу в skeleton-talk

- Уведомления — один способ, тост из лайаута; сейчас не построено.
- Список с фильтрами — своя обёртка `AppTable` над DataTable; не построено.
- Состояния экрана — все, включая «нет прав»; сейчас только у входа.
- Права — политики на каждую модель; сейчас нет ни одной.
- Организации и область прав по локации — не сейчас; сначала роли без
  области.
- Идентификаторы наружу — uuid v7 с первой миграции у лота и комплекса.
- Справочники — таблицы `dict_*` с `code` и `is_system`; первый —
  застройщики? Нет: застройщик — сущность, не справочник. Первый
  справочник появится с лотом (отделка).
- Транзакции — действие, меняющее две таблицы, оборачивается само.
