## Тест приходит своим коммитом и раньше кода — это видно по истории

Правило одно и держится не на том, кто пишет, а на порядке: **тест меняется
только коммитом с трейлером `Orch-Step: tests`, и такой коммит идёт раньше
кода, который он проверяет**. Реализация коммитит так тесты плана; Правки —
тест на находку, красный на текущем коде, перед своей правкой.

Отсюда две ошибки, и скрипт ловит обе:

- файл теста в коммите без трейлера `tests` — тест подкрутили заодно с кодом;
- нетестовый файл в коммите с трейлером `tests` — под видом тестов уехал код,
  и доказательство «сначала тест» становится враньём (прогон T26: 87 файлов
  бэкенда одним коммитом с трейлером `tests`).

Любая из них — блокирующая находка для того, кто её нашёл: назвать, довести до
владельца, никогда не чинить правкой, переносом, удалением теста или
переписыванием истории.

Скрипт запускают Реализация (в конце хода), Правки (в конце хода) и Ревью кода
(каждый заход) и вставляют его вывод дословно в свой файл. Входы: стартовый
коммит задачи из блока задачи и шаблоны файлов тестов из
`scoping.md#Тесты и проверки`, через пробел.

```sh
START=<стартовый коммит> PATTERNS='<glob> <glob>' sh <<'EOF'
set -fu
: "${START:?стартовый коммит}"
: "${PATTERNS:?шаблоны файлов тестов}"
g() { git -C "${REPO:-.}" "$@"; }
status=0
for c in $(g rev-list --reverse "$START..HEAD"); do
  step=$(g show -s --format=%B "$c" \
    | sed -n 's/^Orch-Step:[[:space:]]*//p' | tail -n 1)
  for f in $(g show --pretty=format: --name-only "$c"); do
    is_test=no
    for p in $PATTERNS; do
      case "$f" in $p) is_test=yes; break ;; esac
    done
    # Тест без трейлера `tests` — подкручен заодно с кодом.
    # Нетестовый файл под трейлером `tests` — код уехал под видом тестов.
    if [ "$is_test" = yes ] && [ "$step" != "tests" ]; then
      printf '%s %s [%s] тест вне коммита тестов\n' "$c" "$f" "${step:-no trailer}"
      status=1
    elif [ "$is_test" = no ] && [ "$step" = "tests" ]; then
      printf '%s %s [tests] не тест в коммите тестов\n' "$c" "$f"
      status=1
    fi
  done
done
if [ "$status" -eq 0 ]; then echo "test ownership: ok"
else echo "test ownership: FAIL"; fi
exit "$status"
EOF
```

Каждая строка вывода — `<коммит> <файл> [<трейлер>] <что не так>`; код
возврата ненулевой, если такие есть. Нет шаблонов в `scoping.md` — проверка
невозможна, так и напиши, не угадывай. Нет самого `scoping.md` (короткая
цепочка без разведки, пропущенный шаг, задача начата с середины) — определи
шаблоны по раскладке тестов репозитория, назови их в своём файле рядом с
выводом скрипта и запусти проверку. Здесь угадывать не из чего, а не
проверять — хуже.
