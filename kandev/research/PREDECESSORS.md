# Что взять у KitLight и AgentKit

Разбор 2026-09-04 двух прежних попыток владельца: `kit-lite` (много
маленьких ролей, прямой предшественник Deep) и `agent-kit` (полностью
автономная разработка по «чертежу» продукта). Только то, чего в цепочке
нет; уже принятое и осознанно отвергнутое перечислено в конце.

## Взять сейчас

1. **Потолок объёма задачи** (kit-lite `roles/slicing.md`, `roles/check.md`).
   Planning пишет в «Границы» число файлов к изменению, Plan Review блокирует
   превышение порога из `AGENTS.md` — «сократить или разбить». Final
   Verification кладёт `git diff --stat` в артефакт, Draft PR выносит число
   в описание. Защищает единственное дорогое место — приёмку.
2. **Три ответа над сгибом PR** (agent-kit `rules/pull-requests.md`,
   `skills/accept`). К «Не решено» добавить «Решено без вас» — допущения и
   отклонения от плана после Plan Approval, с пометкой «дорого ошибиться:
   данные | права | деньги | внешний контракт» — и «Нужны ваши руки» —
   секрет, миграция, DNS, с командой-проверкой. Draft PR читает
   `test-authoring.md` и `verification.md`, которых сейчас не читает.
3. **Потолок чтения на воротах** (kit-lite `roles/gate.md`). Первый блок
   `plan-review.md` и `solution-synthesis.md` — не больше десяти строк:
   вердикт, блокирующее, что решать человеку. Списки не резать.
4. **SHA прогона** (agent-kit `skills/ship`). `verification.md` и
   `final-verification.md` записывают `git rev-parse HEAD` прогона; Draft PR
   сверяет с HEAD ветки, расхождение — в «Не решено».
5. **Ведомость долга в репозитории** (agent-kit `templates/technical_debt.md`).
   «Отложить как долг» из Planning, незакрытые minor из Review Fixes и
   «осталось незадокументированным» из Documentation сейчас умирают вместе с
   артефактами. Одна строка в `docs/technical_debt.md` проекта; закрывает
   только тот, кто сделал работу, удалением строки в том же коммите.
   Discovery и Scoping читают.
6. **Вопрос с рекомендацией первой; фиксированный набор вердиктов**
   (agent-kit `rules/asking.md`, `docs/design/method.md`). По строке в
   протокол и в Scoping, Research, Planning.
7. **Версии из lock-файлов, не из манифеста** (kit-lite `roles/check.md`).
   Одна строка в Discovery.

## Взять позже

- **debug**: при возврате с Verification — воспроизвести, одна гипотеза за
  раз, наблюдение до правки. После первых задач, если возвраты не помогают.
- **retro**: отдельная одноколоночная цепочка после слияния: какие правки
  внёс человек после агентов, какая роль пропустила. После пяти PR.
- **map.sh**: детерминированная карта репозитория и версий в Discovery
  heredoc'ом, ноль токенов. Когда увидим, сколько Discovery стоит.
- **design**: таблица состояний экрана (пусто / загрузка / ошибка / успех)
  в Planning для задач с интерфейсом. С первой UI-задачей.
- **Хук против слияния и force-push** (agent-kit `hooks/guard.py`) — в
  `.claude/settings.json` целевого проекта через Conventions; парсить
  refspec, не регэксп; проверить, что агент Kandev подхватывает проектные
  хуки.
- **Мутационный прогон** — только как вопрос владельцу в Conventions.

## Путь к автономии (не сейчас)

0. **Измерить.** Не меньше 15 задач на Deep с записью по каждым воротам
   «принял / вернул, куда, почему» и стоимостью на задачу
   (`on_budget_alert`). Урок agent-kit: шесть версий никогда не
   сравнивались, обсуждение кита съело четверть недели.
1. **Первыми уходят Plan Approval.** Plan Review на другом профиле модели,
   и при вердикте без находок и без открытых вопросов сам прыгает через
   ворота на Test Authoring (`move_task_kandev`, локальный прыжок с
   проверяемой предпосылкой). Иначе карточка встаёт в ворота как сегодня.
   Риск: планировщик и рецензент ошибаются одинаково.
2. **Solution Approval становится окном.** Вопрос с рекомендованным
   вариантом; `on_heartbeat` через N минут отвечает рекомендацией и пишет
   допущение «дорого ошибиться». Ответ после окна применяется только
   возвратом карточки.
3. **Бэклог как родительская задача.** Описание продукта в репозитории
   (`docs/knowledge/`, пишет своя цепочка вроде Conventions); родитель
   заводит детей на Deep через `create_task_kandev`, порядок —
   `add_task_dependency_kandev`, запуск по `on_blocker_resolved`, общие
   решения партии — документы задачи (видны детям), `wip_limit` = 1,
   следующая партия по `on_children_completed`. Риск: каскад блокировок от
   умершей сессии — нужен `on_agent_error` с различением «упал агент» и
   «не вышла задача».
4. **Human Review → политика слияния по классу изменений.** CI зелёный,
   нет blocker/major, владение тестами ok, SHA прогона = HEAD, и хотя бы
   одна улика не от модели (Semgrep/CodeQL). Сначала только документация и
   зависимости. Риск: отката нет.
5. **Непрерывный режим.** Родитель берёт следующее сам, `on_heartbeat`
   сторожит застрявшие карточки, `on_budget_alert` — потолок. Стартует
   владелец, не cron.

Чего не повторять из agent-kit: страховка от собственной автономии (27 М
токенов на фичу, слои правил), проверки на слове агента и на регэкспах,
молчаливые отказы, циклы без потолка, записи без закрывающего, поздние
ответы поверх построенного, сценарии продукта, которые никто не прошёл с
владельцем.

## Уже есть или отвергнуто осознанно

Задача словами человека (`{{task_prompt}}` + решение 42); triage и выбор
маршрута (решение 14); автор тестов не видит реализации (решение 9);
чеклист безопасности (решение 7); остановка на блокере (решения 27–28);
«промолчать» в ревью (сознательно наоборот); профили моделей (решение 12,
вернуться вместе с retro); «готовое вместо своего» (решение 18, Источники);
повторное ревью по прошлым находкам (решение 35); два касания человека
(ворота + вопросы одним вызовом, решение 23); контекстные потолки и
handoff-ноты (Kandev делает сбросом и сессией задачи).
