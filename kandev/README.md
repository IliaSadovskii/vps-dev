# Наполнение доски Kandev

Роли агентов и цепочки шагов, которыми они складываются в работу.
Каталог намеренно самодостаточен: кроме файлов здесь и работающего Kandev,
ему ничего не нужно — ни Ansible, ни этой машины, ни этого репозитория.

```
prompts/      роль = один промпт. Имя файла (без .md) — имя промпта в Kandev
workflows/    цепочка шагов в переносимом формате Kandev (version 1)
profiles.yml  профили агентов (модель, режим, автоодобрение), на которые
              ссылаются колонки; нет агента на машине — колонка без профиля
```

Проектируемые цепочки — три маршрута разной глубины `Quick`, `Standard`,
`Deep` с общим началом (`Backlog`, `Discovery`, `Scoping`) и общим хвостом;
их состав и обоснование в
[`Маршруты разработки`](DEVELOPMENT-ROUTES.md). Дорожку выбирает человек,
заводя карточку, — отдельной колонки выбора маршрута нет.

Сейчас в `workflows/` лежат `deep.yml` — основная дорожка разработки — и
две служебные цепочки на два хода: `conventions.yml` заводит или
обновляет `AGENTS.md`/`CLAUDE.md` проекта, `blueprint.yml` раскладывает
рассказ владельца о продукте по описанию в `docs/knowledge/` (продукт,
акторы, сущности, действия, экраны, интеграции, сценарии, стек; форма —
в `prompts/custom-knowledge-shape.md`). Conventions стоит прогнать до
первой задачи на Deep: роли Deep читают `AGENTS.md` первым после каждого
сброса памяти. Blueprint необязателен: когда `docs/knowledge/` есть, роли
Deep читают его наравне с `AGENTS.md` и в него не пишут; когда нет —
работают как прежде. Quick и Standard убраны, пока проектируется сам поток; они
выводятся из `Deep` вычитанием колонок и будут восстановлены из него.

Все личные prompts имеют префикс `custom-`, чтобы не пересекаться со
встроенными и сторонними именами.

Общий контракт передачи результатов подключён ко всем трём цепочкам через
workflow-level prompt `@custom-artifact-protocol`; его формат описан в
[`Маршрутах разработки`](DEVELOPMENT-ROUTES.md).

## Почему промпты отдельно от цепочек

В Kandev промпт шага — обычное текстовое поле, и написанный прямо там текст
роли пришлось бы повторять в каждой цепочке, где эта роль встречается.
Поэтому роли живут отдельной сущностью, а шаг ссылается на неё через `@имя`.
Разворачивает ссылку в текст роль `seed` при выкатке (и скрипт ниже): сам
Kandev делает это не на всех путях — после сброса памяти и в ходе по
сообщению человека агент получает `@имя` буквально. Так `@custom-implementation` описан один раз, а
работают им и `Quick`, и `Standard`, и `Deep` — поэтому три дорожки с общим
хвостом стоят дёшево: дублируется только скелет колонок, не смысл ролей.

Следствие: цепочку без промптов заводить бессмысленно. Сначала промпты,
потом цепочки — в этом порядке их и ставит роль `ansible/roles/seed`.

## Как это попадает в Kandev

На сервере — само, ролью `seed` при каждом `make apply`. Она добавляет и
обновляет, но никогда не удаляет: встроенные промпты Kandev и цепочка
«Development» остаются на месте.

На своей машине без сервера — двумя запросами к локальному Kandev
(по умолчанию `http://127.0.0.1:8064`):

```sh
KAN=http://127.0.0.1:8064/api/v1
WS=$(curl -s "$KAN/workspaces" | python3 -c 'import sys,json;print(json.load(sys.stdin)["workspaces"][0]["id"])')

for f in prompts/*.md; do
  python3 -c "import json,sys,pathlib
p=pathlib.Path('$f')
print(json.dumps({'name':p.stem,'content':p.read_text()}))" \
  | curl -s -X POST -H 'Content-Type: application/json' --data-binary @- "$KAN/prompts"
done

python3 - <<'PY' | ../ansible/roles/seed/files/kandev-seed-workflows
import glob, json, os, yaml
print(json.dumps({"api": os.environ.get("KAN", "http://127.0.0.1:8064/api/v1"),
                  "workspace_id": os.environ["WS"],
                  "prompts": {os.path.basename(f)[:-3]: open(f).read()
                              for f in glob.glob("prompts/*.md")},
                  "files": [{"name": os.path.basename(f), "doc": yaml.safe_load(open(f))}
                            for f in sorted(glob.glob("workflows/*.yml"))]}))
PY
```

Повторный запуск безопасен: промпт с занятым именем вернёт 409, цепочка
с занятым именем обновится на месте, а без изменений попадёт в
`unchanged`.

## Правка

Правьте файлы здесь, не в интерфейсе. Роль `seed` при следующем прогоне
обновит и промпты, и цепочки по содержимому: цепочку она находит по имени,
колонки — по именам внутри неё, и сохраняет их идентификаторы, поэтому
задачи, стоящие в колонках, остаются на месте. Колонку, которую вы убрали
из файла, она удалит, только если в ней нет задач; иначе цепочка не
трогается, а прогон скажет, какую колонку освободить.

Отсюда правило: имя цепочки и имена колонок — это ключи. Переименование
колонки в файле для доски выглядит как «одну удалить, другую создать»,
и задачи в старой колонке этому помешают.

Удалять `seed` не умеет ничего: ни цепочки, ни промпты. Файл пропал —
на доске остаётся, пока не удалите руками в интерфейсе.

Дальше этот каталог может уехать в отдельный репозиторий: формат файлов
в `workflows/` — тот самый переносимый формат, который умеет читать
Workflow Sync (`.kandev/workflows` в репозитории на GitHub или GitLab).
Тогда цепочки будет возить сам Kandev, а роли `seed` останутся промпты.
