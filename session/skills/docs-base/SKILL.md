# docs-base

Ты приводишь к общей форме то, что агент читает при старте каждой сессии,
и всё, на что оно ссылается. Самый опасный файл — `AGENTS.md`: он едет в
контекст всегда, лишняя строка стоит дороже пропущенной. Поэтому это не
«сгенерируй», а «собери кандидатов из всего, что есть, и по каждому реши».
Ход один для любого проекта; различается только сырьё:

| Состояние | Сырьё для черновика |
|---|---|
| пустой | ответы владельца; сценариев ещё нет |
| код без `AGENTS.md` | код, тесты, комментарии, сборка, CI, ADR, если есть |
| код и разросшаяся документация | всё то же плюс старый `AGENTS.md` и `docs/**` — каждая их строка кандидат, ничего не выбрасывается без показа |

Прочитай перед началом, целиком:
- `../FORMAT.md` — пять файлов, классы знания и куда едет каждый, разделы
  `AGENTS.md` с бюджетом, сторож;
- `../PRINCIPLES.md` §2, §3, §4, §6, §7, §8, §9;
- `../asking.md` — правила опроса;
- `../../sample/AGENTS.md`, `../../sample/docs/README.md`,
  `../../sample/docs/decisions/` — **только форма**: разделы, порядок,
  колонки, длина. Содержимое образца («Переговорки») не переносится ни
  строкой, даже там, где строка выглядит общей (стоп-лист, git, «никогда»).

Кода не пишешь. Раздел «Каркас» не заполняешь, сценарии не пишешь.
Репозиторий может быть занят другой сессией — работай в отдельном
worktree.

## Шаг 0. Инвентаризация — без правок

Собери, не спрашивая: README, все цели `Makefile` (`make help`), профили
`docker-compose.yml`, шаги CI, манифесты и lock-файлы, раскладку каталогов,
тесты по видам, линтеры и их конфиги, скрипты проверок, `AGENTS.md` /
`CLAUDE.md` / `docs/**`, файлы правил других клиентов (`.cursor/rules`,
`.claude/rules`, `copilot-instructions.md`), комментарии-эссе в коде
длиннее двух строк. По каждому документу: строк, дата последней правки
(`git log -1 --format=%cs -- файл`), кто на него ссылается.

Каждую команду, которую собираешься записать, **запусти**; запускаешь
только неразрушающие — `fresh`, `destroy`, `reset`, `down -v` читаешь,
записываешь с пометкой и не запускаешь. Не запустилась — не записывай.

`docs/`, которые не читаются каждую сессию, **не сокращаются**: цена у
них нулевая, пока они не врут. Режется только `AGENTS.md`.

## Шаг 1. Продукт — один открытый вопрос, если ответа нет

Единственное место, где нужен рассказ, а не выбор: что за продукт, кому,
что значит «готово», что продуктом не является. Ответ уже есть в README,
старом `AGENTS.md` или документах — покажи, что понял, спроси только о
расхождениях. Нет нигде — спроси один раз. Запиши 6–10 строк. Критерий
«готово» — цель, не описание состояния.

## Шаг 2. Черновик из сырья — до вопросов

Собери черновик разделов `AGENTS.md` по `FORMAT.md` §3 (кроме «Каркаса»):

| Раздел | Откуда |
|---|---|
| Проверить себя, поднять | цели `Makefile`, профили compose, шаги CI, README |
| Когда остановиться и спросить | список `FORMAT.md` §3 как основа; из старого `AGENTS.md` — что там было |
| Стек и чего не брать | lock-файлы: имена пакетов, **без версий**; «не брать» — из старых документов, остальное спросишь |
| Где что лежит | только каталоги вне умолчаний фреймворка и то, что из дерева не выводится |
| Правила | (а) существующие проверки: арх-тесты, тесты с правилом в названии, скрипты, шаги CI, конфиги линтера — каждая проверка → правило; (б) конвенции по коду — «(по двум примерам)»; (в) правила из старого `AGENTS.md` и `docs/`; (г) сказанное владельцем — после вопросов |
| Ловушки | комментарии в коде, объясняющие обход или странность, — каждый кандидат; ловушки из старых документов; спросишь: «на чём агент уже ошибался». Пустой проект — ловушек нет по определению, раздел не заводится, а требование владельца записывается правилом с проверкой, не ловушкой |
| Стиль решений | повторяющиеся образцы в коде: где Data, где Actions, где значения |
| Тесты | виды по каталогам и конфигу тестов; статус «есть» только тому, что запускается; «отложено / отклонено / одобрено» — из документов или от владельца |
| Git | ветки из истории, форма коммитов из `git log`, форма описания PR — из образца |
| Что читать перед задачей | существующие `docs/*` с условием чтения |

Проект пустой — черновика из кода нет: разделы «Проверить себя», «Стек»,
«Правила», «Тесты», «Git» собираются пачками вопросов с вариантами и ценой;
«Где что лежит», «Ловушки», «Что читать перед задачей» не заводятся —
нечем.

Есть старая документация — параллельно размечай каждый её кусок по классу
из `FORMAT.md` §2: правило, решение, ловушка, каркас (отложить для
`docs-skeleton`), замысел, описание состояния, знает сама. Разбор
вариантов с датой и пометкой «принято» — ADR со ссылкой обратно; без даты
посреди документа — тоже ADR, дата из `git log`. Решение, найденное в
комментарии кода, — ADR без правки кода.

## Шаг 3. Фильтр каждой строки-кандидата

1. **Удалить — агент ошибётся?** Нет, или ответ даёт команда за десять
   секунд — вычеркнуть (списки файлов, версии, что сделано, как работает).
2. **Модель знает сама?** «PSR-12», «пишите тесты» — вычеркнуть.
3. **Правило без проверки** — пожелание: найти проверку, предложить новую
   владельцу (не писать самому) или оставить с «ревью» по его решению.
4. **Ловушка** — факт вне кода, на котором ошибались; пометка «(ловушка)»;
   три и больше про одну область — `docs/rules/<область>.md` и строка в
   «Что читать перед задачей»: «правишь `<маска>` — сначала
   `docs/rules/<область>.md`».
5. **Описание состояния** — удалить или заменить командой, тестом,
   `git log`. Дешёвые утверждения («vendor не установлен», «модуль один»)
   проверь командой; статусы проверок и стоп-пункты не удаляй, а сверь:
   вид запускается — «есть», стоп-пункт закрыт принятым ADR — снять.
6. Абзац длиннее трёх строк — в `docs/<тема>.md`, здесь ссылка. Номера
   строк не пишутся.

Правило владения (`FORMAT.md` §2): дубль между слоями снимается в пользу
хозяина.

## Шаг 4. Показать и спросить — только о дырах и спорном

Покажи владельцу целиком: черновик по разделам; если была документация —
раскладку переезда (что остаётся, что уезжает куда, что удаляется и
почему, ожидаемый размер; ADR-кандидаты — заголовок, дата из `git log`
куска, откуда вырезан). Вычеркнутое — отдельным списком «убрал, потому
что». Ничего не удаляется без строки в этом списке.

Спрашивай пачками по 4–6, варианты с ценой, рекомендуемый первым
«(рекомендую)». Не спрашивай того, что есть в коде, и того, где все ответы
ведут к одной работе — реши, пометь «(допущение)». Что обычно остаётся:
«чего не брать»; правила без проверки — какой исход; ловушки; виды
проверок, которых нет — статус; стоп-лист — что добавить; git — «никогда»;
кусок, который читается и как правило, и как состояние; удаление куска, на
который ссылаются. После пачки: «что я не спросил, но здесь важно?».
Ответы — в файл сразу, с пометкой «выбор владельца»; «не знаю» — открытый
вопрос в `docs/README.md`. Владелец сказал — записывается, даже если
фильтр не пропускает.

## Шаг 5. Записать

- `AGENTS.md` по форме образца и бюджету `FORMAT.md` §3; раздел «Каркас»
  — заголовок и правило под таблицей из образца дословно, таблицу заведёт
  `docs-skeleton`. Была старая таблица каркаса — оставь её как есть, не
  трогай. Сторож на ней будет красный (пустая таблица или путь в колонке
  «Правило») — скажи владельцу в отчёте, правка за `docs-skeleton`.
- `CLAUDE.md` — одна строка `@AGENTS.md`; файлы правил других клиентов —
  спросить: свести или удалить.
- `docs/README.md` — карта по форме образца, первая строка «правда — код и
  тесты; документы говорят, где искать и почему так решили», открытые
  вопросы.
- `docs/decisions/` — ADR по форме образца на каждое решение из документов
  и комментариев; нумерация по правилам журнала проекта, нет журнала —
  завести по форме. Ссылку на ADR в комментарий кода — отдельным пунктом
  отчёта, сам не правишь.
- `docs/<тема>.md` — вырезанный замысел; правил и решений там нет, только
  ссылки. Ссылки на переехавшее поправить (`grep -rn`).
- `scripts/check-agents.sh` — копия `../../sample/scripts/check-agents.sh`,
  в `make lint` и CI тем же способом, что остальные проверки. Нет ни
  `Makefile`, ни CI — открытый вопрос в `docs/README.md`: «подключить тем
  же PR, что заведёт сборку».
- Один коммит на ход: «вырезано в ADR», «AGENTS.md по форме», «карта docs/».

## Шаг 6. Проверить себя

- каждая команда в разделе 1 запускалась в этой сессии;
- `AGENTS.md` без строк таблицы каркаса ≤ 150; абзацев длиннее трёх строк
  нет; номеров строк нет; у правила есть «проверка», у ловушки пометка;
- ни одного куска класса «описание состояния»; ни одной строки, которую
  модель знает без файла; ни одной строки из образца по содержанию;
- каждый ADR датирован, имеет статус и «Где»; битых ссылок в `docs/` нет;
- сторож зелёный или красный только по таблице каркаса.

Заверши отчётом: было → стало для `AGENTS.md`; что вычеркнул и почему;
сколько ADR и откуда; что «(допущение)»; открытые вопросы; строка
«следующий шаг: `docs-skeleton`».

## Чего не делать

- Не спрашивать открытыми вопросами ни о чём, кроме продукта.
- Не ссылаться на образец как на довод: довод — код проекта или владелец.
- Не заводить раздел под то, чего ещё нет («появится позже»).
- Не заполнять «Каркас», не писать сценарии.
- Не писать код, тесты, проверки; комментарий-эссе в коде — ADR, файл не
  править.
- Не удалять молча; не переписывать смысл — переезд, не редактура.
- Не заканчивать ход списком вопросов в тексте или обещанием: вопросы
  интерактивно, ход — результат или вопрос.
