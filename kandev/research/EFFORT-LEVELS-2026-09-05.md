# Уровни усилий (effort) у Claude и Codex: когда высокие оправданы

Обзор 2026-09-05 по документации Anthropic и OpenAI, замерам и
опыту сообщества. Источники — ссылками у каждого факта; чего не
нашлось, сказано прямо.

## Итог в пять строк

1. У обоих провайдеров рабочий дефолт для кодинга — `high` (Codex:
   `medium`, по опыту людей `high`). Не трогать без замера.
2. `xhigh` окупается на планировании, сложной отладке, изменениях
   через несколько модулей и долгих автономных прогонах. На рутине
   даёт только время и токены.
3. `max` — для задач на пределе возможностей модели, после проверки,
   что `xhigh` не хватило. Склонен к перегибу: у Opus 4.8 на одном
   бенчмарке `max` хуже `xhigh`.
4. `low`/`medium` — субагенты-разведчики, переименования, конфиги,
   правки в одном файле. На Opus 5 и Fable `low`/`medium` часто
   сильнее `xhigh` прошлого поколения.
5. Уровень с одним именем у разных моделей — разное количество
   размышления; настройка не переносится, при смене модели
   перемерять.

## Что говорит Anthropic

### Уровни и механика в Claude Code

- Уровни `low`, `medium`, `high`, `xhigh`, `max` и режим `ultracode`.
  Управление: `/effort <уровень>`, `effortLevel` в settings (только до
  `xhigh`, `max` не сохраняется), `CLAUDE_CODE_EFFORT_LEVEL`,
  `--effort`, `effort:` во frontmatter субагента или skill.
  <https://code.claude.com/docs/en/model-config>
- По умолчанию `high` у всех моделей с поддержкой effort, кроме Opus
  4.7 — там `xhigh`. `xhigh` есть у Fable 5/5.1, Opus 5, Sonnet 5,
  Opus 4.8, 4.7; на Opus 4.6 работает как `high`. Там же.
- `max` в доке Claude Code: «может улучшить результат на требовательных
  задачах, но показывает убывающую отдачу и склонен к overthinking;
  проверьте, прежде чем применять широко». Там же.
- `ultracode`: «планирует динамический workflow для каждой
  содержательной задачи с `xhigh` на каждое сообщение». Включается
  `/effort ultracode` или `claude --effort ultracode`; в настройках не
  сохраняется. Отдельной страницы документации нет. Там же.
- `ultrathink` — не уровень: слово в промпте добавляет подсказку
  «подумай глубже» в контекст, уровень effort в API не меняется.
  Слова «think», «think hard» не распознаются. Там же.
- История: 4 марта 2026 дефолт понизили до `medium` ради скорости,
  7 апреля откатили после жалоб; итог — `xhigh` для Opus 4.7, `high`
  для остальных.
  <https://www.anthropic.com/engineering/april-23-postmortem>
- Claude Code 2.1.251: `/effort` запоминается на каждую модель отдельно;
  2.1.261: на Fable 5.1 смена effort посреди сессии больше не сбрасывает
  кэш промпта. <https://code.claude.com/docs/en/changelog>

### Рекомендации по уровням в документации платформы

<https://platform.claude.com/docs/en/build-with-claude/effort>

| Уровень | Для чего |
|---|---|
| `low` | простые задачи, где важны скорость и цена, «например субагенты» |
| `medium` | агентные задачи, где нужен баланс |
| `high` | сложное рассуждение, трудные задачи кодинга, агентная работа |
| `xhigh` | долгие агентные и кодинговые задачи (больше 30 минут) с бюджетом в миллионы токенов |
| `max` | самое глубокое рассуждение |

По моделям:

- **Opus 4.7/4.8**: «начинайте с `xhigh` для кодинга и агентных
  задач»; `high` — минимум для чувствительных к интеллекту задач;
  `max` — «для frontier-задач; на большинстве нагрузок добавляет
  заметную стоимость при небольшом выигрыше, а на структурированном
  выводе ведёт к overthinking». Opus 4.8 в анонсе: «`high` — лучший
  баланс, тратит столько же токенов, сколько дефолт 4.7, при лучшем
  результате; `extra` — для трудных задач и долгих асинхронных
  прогонов; лимиты Claude Code подняты под высокие уровни».
  <https://www.anthropic.com/news/claude-opus-4-8>
- **Opus 5**: «начинайте с `high` (дефолт), поднимайте до `xhigh` для
  требовательного кодинга, до `max` когда задача оправдывает
  неограниченный расход; `low` и `medium` используйте свободно».
  Пришли с прошлой модели — перемерьте. На `xhigh`/`max` thinking не
  отключается (400). Код-ревью «точен и на низких уровнях: дешёвый
  быстрый проход на ревью плюс тщательный позже — рабочий приём».
  Effort не укорачивает видимый ответ — это делает промпт.
  <https://platform.claude.com/docs/en/models/opus-5/whats-new-opus-5>
- **Sonnet 5**: дефолт `high`; `xhigh` — для самых трудных задач;
  Sonnet 5 на `medium` ≈ Sonnet 4.6 на `high`, на `high` ≈ 4.6 на
  `max`. На `low`/`medium` «есть риск недодумать»; если видно мелкое
  рассуждение — поднимать effort, а не промптовать вокруг. На
  `high`/`xhigh` «заметно больше вызовов инструментов».
  <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5>
- **Fable 5/5.1**: дефолт `high`, `xhigh` — для самых чувствительных
  к способностям нагрузок; «низкие уровни на Fable часто превосходят
  `xhigh` прошлых моделей». Предупреждение: «на рутине при высоком
  effort Fable собирает контекст и размышляет сверх нужного» — есть
  готовая строка промпта против незапрошенного рефакторинга. Один
  запрос на трудной задаче — многие минуты. У 5.1 прирост над 5
  «больше всего на высоких уровнях; на `medium` примерно равен Fable 5
  дешевле».
  <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5>
  <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1>

### Замеры Anthropic (из справочника Claude API и системных карт)

- Долгий кодинг, Opus 5: `medium` теряет около 2 пунктов за половину
  цены, `low` — около 8 пунктов за четверть.
- Исследовательская работа, Fable 5: кривая почти плоская — `low`
  теряет 1–3 пункта за треть-половину цены, `medium` равен дефолту при
  70–85 % цены; дефолт не дал ничего измеримого сверх `medium` ни на
  одном из четырёх бенчмарков. `low` ещё и быстрее: 4,5 против 7,9
  минуты на задачу.
- Приём «всё на `low`, провалы перегнать на дефолте»: 93 % за 0,70 $ на
  задачу против 91,7 % за 1,39 $ при всём на дефолте. Работает только
  там, где есть сигнал провала (тесты, проверка).
- Системная карта Fable 5 (пересказ chudi.dev): SWE-bench Pro — Opus 4.8
  `low` 60,3 / `xhigh` 68,6; Fable 5 `low` 75,0 / `xhigh` 80,4, то есть
  Fable на `low` выше Opus 4.8 на `xhigh`. FrontierCode Diamond: Opus
  4.8 `xhigh` 13,4, `max` 11,4 — `max` хуже.
  <https://chudi.dev/blog/claude-fable-5-vs-opus-4-8>
- Сторонние пересказы карты Opus 5: пик FrontierCode на `medium`,
  `high` — плато. Первоисточник не проверен.

## Что говорит OpenAI

- Уровни `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`.
  Дефолт GPT-5.5 и 5.6 — `medium`, «лучшая точка старта». Таблица:
  `low` — вызовы инструментов, планирование, поиск; `medium` — дефолт,
  агентный кодинг, исследование; `high` — трудное рассуждение, сложная
  отладка, глубокое планирование; `xhigh` — глубокое исследование,
  асинхронные и долгие агентные прогоны; `max` — «максимум для самых
  сложных задач». Для агентного кодинга — «`medium` и `high`, оцените
  оба». <https://developers.openai.com/api/docs/guides/reasoning>
- `max` только у GPT-6 и GPT-5.6 через Responses API; `xhigh` у GPT-6,
  5.6, 5.5, 5.4, `gpt-5.1-codex-max`. Про `xhigh`: «используйте, когда
  ваши evals показывают выигрыш, оправдывающий задержку и цену»; про
  `max`: «если сейчас `xhigh`, сравните оба, прежде чем переключаться».
  <https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/reasoning>
- Codex CLI: `model_reasoning_effort` (`minimal`…`xhigh`),
  `plan_mode_reasoning_effort` (по умолчанию пресет, сейчас `high`),
  `agents.default_subagent_reasoning_effort`.
  <https://learn.chatgpt.com/docs/config-file/config-reference>
- Модели Codex (Astra, 5.6 Sol, Terra, Luna): уровни Light … Ultra;
  правило «используйте самый низкий уровень, который даёт нужный
  результат»; Sol — «неоднозначные, трудные, дорогие задачи», Luna —
  «конкретные массовые задачи». <https://learn.chatgpt.com/docs/models>
- Субагенты Codex: `ultra`/`max`/`xhigh` — особо требовательное
  рассуждение; `high` — проследить сложную логику, проверить допущения
  и края; `medium` — баланс для большинства; `low` — простое и быстрое.
  <https://learn.chatgpt.com/docs/agent-configuration/subagents>
- Codex prompting guide: `medium` — «хорошая универсальная интерактивная
  модель», `high`/`xhigh` — «для самых трудных задач». GPT-5 guide:
  понижать effort, чтобы «ограничить побочные вызовы инструментов»;
  «для сложных многошаговых задач — выше». GPT-5.2 guide: менять
  effort «только после прогона evals».
  <https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide>
- Ultra у 5.6 Sol — параллельные субагенты, закрытое превью; по опыту
  сообщества 6–12× токенов на больших задачах и +15–20 % на
  оркестрацию, без ускорения на связанных правках одного файла.
  <https://codex.danielvaughan.com/2026/07/24/codex-cli-ultra-mode-trade-off-reasoning-budgets-subagent-cost-task-routing/>
- Официальных бенчмарков «по уровням с ценой» у OpenAI не найдено;
  анонсы 5.5 и 5.3-Codex отдавали 403.

## Что говорит сообщество

1. **GPT-5.5 Codex, 26 реальных задач, четыре уровня** (stet.sh): тесты
   81/81/96/92 %, эквивалентность PR 15/42/69/88 %, проход ревью
   12/19/38/69 %, цена 2,65/3,13/4,49/9,77 $, время 287/411/579/753 с.
   Вывод: «`high` — дефолт на каждый день, `xhigh` — для неоднозначных,
   сквозных, многопоточных задач и там, где высок риск на ревью».
   <https://www.stet.sh/blog/gpt-55-codex-graphql-reasoning-curve>
2. **90 прогонов агентов** (Mehta, arXiv 2607.02436): подъём с `high` на
   `xhigh` увеличил долю идеальных прогонов с первого раза с 28 % до
   89 % за +9–29 % стоимости; при этом инструмент тестирования добавил
   42–68 % цены без выигрыша. <https://arxiv.org/abs/2607.02436>
3. **PostTrainBench** (arXiv 2603.08640): GPT-5.1 Codex-Max — `medium`
   лучше `high` (19,7 против 17,2) при вдвое меньших токенах; GPT-5.3
   Codex — `high` лучше, но 2,8× токенов и вдвое дольше.
   <https://arxiv.org/html/2603.08640>
4. **Simon Willison**: GPT-5.5 на дефолте — 39 токенов рассуждения,
   `xhigh` — 9 322 и почти четыре минуты, результат заметно лучше;
   про 5.6: «Sol на `medium` может стать новым дефолтом для кода».
   <https://simonwillison.net/2026/Apr/23/gpt-5-5/>
5. **Лимиты Claude**: на Max 5x «Opus только на `xhigh`, насытить
   невозможно, неделю заканчиваю на 30 %» против «пары запросов хватило,
   чтобы исчерпать 5-часовое окно за полчаса»; на Opus 4.7 «каждый обмен
   съедает ~5 % 5-часового лимита вместо 1–2 %»; на Pro «2–4 промпта и
   стена». Зависит от плана и размера контекста.
   <https://news.ycombinator.com/item?id=47893045>
   <https://news.ycombinator.com/item?id=47817737>
6. **«Просто поставь `xhigh`»** (Opus 4.7/4.8): решает 80 % проблем; но
   «`max` только на проверенных случаях», кейс — `max` на пакетном
   переименовании 12 файлов сжёг примерно 50× от `low`; проза на `max`
   «как техническая статья».
   <https://anthonymaio.substack.com/p/opus-47-the-five-effort-levels-in>
7. **Opus 5 перегибает на `xhigh`**: r/ClaudeAI, август 2026 —
   несколько человек получили лучше очерченный результат на
   «med-high», чем на `xhigh`; совет «если Opus 5 передумывает долгую
   задачу, прогоните её на `medium`».
   <https://www.explainx.ai/blog/opus-5-over-engineering-reddit-reaction-august-2026>
8. **Fable выше `high` не окупается** (мнение) против «чем труднее задача
   и выше уровень, тем больше отрыв Fable» (по FC Diamond); Fable
   официально тратит лимит примерно вдвое быстрее Opus за токен.
   <https://www.iwoszapar.com/p/fable-5-extra-effort-before-usage-credits>
9. **`medium` не значит дёшево**: Opus 4.8 на `medium` потратил 46 тысяч
   скрытых токенов рассуждения (22 минуты) на простой grep-and-rename.
   <https://github.com/anthropics/claude-code/issues/64153>
10. **Codex на ревью, Opus на код**: `xhigh` у Codex ловит архитектурные
    ошибки, но код неряшлив по стилю; типичная практика — `high`
    стандарт, `xhigh` «изредка на отладке». Оценка множителей токенов к
    `medium`: `low` ≈ 0,3×, `high` ≈ 3–5×, `xhigh` ≈ 8–15×; родитель на
    `high` + субагенты на `low` экономят 50–70 %.
    <https://news.ycombinator.com/item?id=47799512>
    <https://codex.danielvaughan.com/2026/03/27/reasoning-effort-tuning/>

Где расходятся: Claude для кодинга — «всегда `xhigh`» (Anthropic для
4.7/4.8 и часть пользователей) против «`medium`–`high` лучше держит
границы» (Opus 5). Anthropic для Opus 5 и Fable сама сдвинула
рекомендацию к `high` с «`low`/`medium` свободно». Codex — OpenAI за
`medium`, Mehta за `xhigh`, stet.sh за `high`.

## Подводные камни высоких уровней

- **Время.** `xhigh` на GPT-5.5 — 753 с против 287 с на `low`; Fable на
  `high`+ — «многие минуты, автономные прогоны часами», менять
  таймауты.
- **Лимиты подписки.** Effort действует на все выходные токены, включая
  рассуждение и вызовы инструментов; `xhigh` у Codex — 3–5× токенов к
  `medium`. Anthropic подняла лимиты Claude Code под высокие уровни, но
  на Pro стена наступает за несколько промптов.
- **Перегиб.** `max` «склонен к overthinking» (Anthropic); Opus 4.8 на
  `max` хуже `xhigh` на FC Diamond; GPT-5.1 Codex-Max на `high` хуже
  `medium`; GPT-5.5 на FC Diamond не растёт с effort вовсе; Opus 5 на
  `xhigh` хуже держит границы задачи.
- **Не переносится между моделями.** «Имена уровней не соответствуют
  одному объёму рассуждения у разных моделей» — перемерять после смены.
- **Кэш и `max_tokens`.** Смена effort между запросами сбрасывает кэш
  промпта (кроме Fable 5.1 и Opus 5 через per-message effort); на
  `high`+ чаще упирается в `max_tokens`, нужно 64k+.
- **Стиль.** `max` делает прозу тяжёлой; Codex `xhigh` — сильное
  ревью, неряшливый код. Effort у Opus 5 не укорачивает ответ.
- **Двойная работа.** Opus 5 «проверяет свою работу без указания»;
  инструкции «перепроверь» и лишние шаги верификации на высоком уровне
  добавляют цену без выигрыша (+42–68 % у Mehta).
- **`ultrathink` не поднимает effort.** Нужно больше рассуждения —
  `/effort xhigh` или `max`.
- **Haiku 4.5** параметр effort не поддерживает: значение в профиле
  ничего не меняет.

## Что это значит для доски Kandev

Сейчас в `profiles.yml` все три профиля Claude на `high`, у Codex
уровень не задан (дефолт `medium`). По документации и замерам:

| Колонка | Модель сейчас | Уровень сейчас | Рекомендация |
|---|---|---|---|
| Solution Synthesis, Planning | Opus | `high` | `xhigh`: планирование — где отдача накапливается, а колонка одна |
| Code Review, Security Review, Fix Review | Opus | `high` | оставить `high`: Opus 5 точен на ревью и на низких уровнях |
| Plan Review | Codex | не задан (`medium`) | `high`: OpenAI — «трудное рассуждение, глубокое планирование» |
| Discovery, Scoping, Research, Test Authoring, Implementation, Verification, Review Fixes | Sonnet | `high` | оставить; Discovery можно попробовать `medium` |
| Final Verification, Draft PR, ворота | Haiku | `high` | параметр не действует, убрать, чтобы не вводил в заблуждение |

`ultracode` для колонок не нужен: он планирует workflow внутри одной
сессии, а у нас workflow — сама доска. `max` — нигде, пока не будет
задачи, на которой `xhigh` не справился. Любое изменение — перемерить
на полигоне тем же способом, что в `TRIAL-2026-09-04.md`: время и
токены по колонкам.
