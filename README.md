# vps-dev

Сервер разработки, на котором работают ИИ-агенты. Чистая Ubuntu 24.04 →
одной кнопкой GitHub Actions → доска задач для агентов, чат с агентом,
VS Code, терминал и файлы в браузере, Docker для проектов. Наружу не смотрит
ничего: единственный вход — твоя сеть Tailscale.

## Что получаешь

Одна закладка: `https://<машина>.<сеть>.ts.net/` — страница со ссылками на всё.

| Порт | Служба | Назначение |
|---|---|---|
| 8064 | [Kandev](https://kandev.ai) | доска: задача идёт по шагам, на каждом свой агент |
| 8065 | [Agent of Empires](https://www.agent-of-empires.com) | чат с агентом в браузере и в терминале, сессии в tmux |
| 8063 | VS Code | code-server: редактор, файлы, терминал в одном окне |
| 8066 | Терминал | dinotty: консоль в `/projects`, с телефона тоже |
| 8067 | Файлы | File Browser: вся машина, открывается в `/projects` |
| 8068 | Мониторинг | Beszel: CPU, память, диск по машине и контейнерам |
| 8070 | Лимиты | сколько израсходовано за 5 часов и за неделю: Claude, Codex, z.ai |
| 8069 | Почта | Mailpit: ловушка писем проектов |
| 8060 | Dozzle | журналы контейнеров |
| 8061 | DbGate | клиент баз данных проектов |
| 80xx | проекты | каждый веб-сервис проекта на своём порту |

Агенты: Claude Code, Codex, Gemini CLI, OpenCode — список в `servers.yml`,
ни один не зашит. Всё работает под пользователем `dev` с `sudo` без пароля.
Паролей у служб нет: границу держит Tailscale.

## Установка

Нужно: аккаунт GitHub, сеть Tailscale, VPS с чистой Ubuntu 24.04
(2 ядра, 4 ГБ минимум) и публичным IP.

### 1. Форк

Форкни репозиторий, включи в форке Actions (вкладка Actions → Enable).

### 2. Tailscale

<details>
<summary>Теги, права, два OAuth-клиента, DNS — по шагам</summary>

**Access Controls** (`https://login.tailscale.com/admin/acls`). Объяви теги
и дай им доступ. Если ACL не менялся, всё разрешено по умолчанию и нужны
только `tagOwners`:

```json
{
  "tagOwners": {
    "tag:server": ["autogroup:admin"],
    "tag:ci":     ["autogroup:admin"]
  },
  "acls": [
    {"action": "accept", "src": ["autogroup:member", "tag:ci"], "dst": ["tag:server:*"]}
  ]
}
```

`tag:server` — сервер, `tag:ci` — раннер GitHub на время прогона.

**OAuth-клиенты** (`Settings → OAuth clients → Generate OAuth client`).
Два, чтобы отзывались независимо:

| Клиент | Scope | Tags | Куда |
|---|---|---|---|
| для раннера | `auth_keys` → Write | `tag:ci` | секреты `TAILSCALE_OAUTH_CLIENT_ID`, `TAILSCALE_OAUTH_SECRET` |
| для сервера | `auth_keys` → Write | `tag:server` | секреты `TAILSCALE_OAUTH_SERVER_CLIENT_ID`, `TAILSCALE_OAUTH_SERVER_SECRET` |

Секрет клиента показывается один раз.

**DNS** (`Settings → DNS`): включи MagicDNS и HTTPS Certificates. Без них
не поднимутся адреса `*.ts.net` и дашборд.

Ключ узла руками не нужен: обвязка выпускает серверу одноразовый ключ
клиентом `tag:server` в момент прогона.

</details>

### 3. Машина

<details>
<summary>Образ, ключ, что записать</summary>

При создании машины: образ Ubuntu 24.04, SSH-ключ для root — **открытая
половина** ключа, которым будет ходить кнопка (сгенерируй пару на
ноутбуке: `ssh-keygen -t ed25519 -f ~/.ssh/vps_dev`). Запиши публичный IP.

Брандмауэр у провайдера не нужен: 22 закроет сама настройка, как только
машина войдёт в сеть. Веб-консоль провайдера — запасной вход, для неё
задаётся пароль root (шаг 4).

</details>

### 4. Секреты форка

`Settings → Secrets and variables → Actions → New repository secret`:

| Секрет | Значение |
|---|---|
| `SSH_PRIVATE_KEY` | закрытая половина ключа из шага 3, весь файл |
| `TAILSCALE_OAUTH_CLIENT_ID`, `TAILSCALE_OAUTH_SECRET` | клиент `tag:ci` |
| `TAILSCALE_OAUTH_SERVER_CLIENT_ID`, `TAILSCALE_OAUTH_SERVER_SECRET` | клиент `tag:server` |
| `VPS_DEV_ROOT_PASSWORD` | пароль root для веб-консоли провайдера; сохрани в менеджер паролей |
| `VPS_DEV_NTFY_TOPIC` | топик на [ntfy.sh](https://ntfy.sh) для уведомлений; длинная случайная строка — это пароль |

### 5. Реестр

В `servers.yml` впиши машину и открытый ключ:

```yaml
hosts:
  dev-1:
    dev_public_address: 1.2.3.4
vars:
  base_deploy_ssh_keys:
    - "ssh-ed25519 AAAA… vps_dev"      # ключ из шага 3
    - "ssh-ed25519 AAAA… ноутбук"      # второй, с другой машины
```

Ключей минимум два: список — единственный источник правды о том, кому можно
войти, лишние ключи с машины стираются.

### 6. Кнопка

`Actions → Сервер разработки → Run workflow`:

1. `mode: check`, `machine: dev-1`, ✓ «Первое подключение» — сухой прогон, ничего не меняет.
2. `mode: apply`, те же поля — настройка, около 6 минут.
3. В журнале найди `dev_host_fingerprint: "SHA256:…"`, впиши в блок машины в `servers.yml`. Дальше отпечаток сверяется автоматически.
4. `mode: audit` — снаружи не должно отвечать ничего.

Повторный `apply` даёт `changed=0` и идёт около двух минут: Ansible
выполняется уже на самой машине.

## Первый день

Открой `https://<машина>.<сеть>.ts.net/`, дальше **Терминал**.

### Входы

```bash
cd /projects
gh auth login          # GitHub.com → HTTPS → Login with a web browser → код на экране
gh auth setup-git      # git будет ходить в GitHub с токеном gh
claude auth login
codex                  # в меню: Sign in with ChatGPT
gemini                 # в меню: Sign in with Google
opencode auth login
```

Каждая команда печатает ссылку и код: открой на любом устройстве. SSH-ключ
для GitHub не нужен. Логины общие для Kandev, aoe, терминала и VS Code —
все под `dev`, один раз.

### Первый проект

```bash
cd /projects
git clone https://github.com/<ты>/<репозиторий>.git
cd <репозиторий>
ports claim <репозиторий>   # блок из 10 портов, например 8010-8019
make up                     # или как принято в этом проекте
```

Проект поднимает себя сам. Что ему нужно знать про эту машину — порты, прокси,
ловушку почты, правила общежития — [`docs/MACHINE.md`](docs/MACHINE.md).

## Службы

<details>
<summary><b>Kandev</b> — доска задач, порт 8064</summary>

Репозитории из `/projects` находит сам. CLI агентов видит установленные;
если чего-то нет — Settings → Agents → Rescan.

Один раз: Settings → GitHub → способ «GitHub CLI» (после `gh auth login`),
либо токен.

Задача: репозиторий и базовая ветка → профиль агента (executor
**Worktree**: отдельная копия под каждую задачу) → описание.

Роли агентов и цепочки шагов приезжают из [`kandev/`](kandev/) при каждой
выкатке — роль `seed`, только добавляет и обновляет, ничего не удаляет.
Править их надо файлами там, а не в интерфейсе.

Быстрый способ применить правку — из терминала на самой машине:

```sh
cd vps-dev && make board   # git pull и наполнение доски, секунды
```

Секретов ему не надо: доска слушает loopback, а туда с самой машины можно
без ключей. Снаружи то же делает обычная выкатка, только тратит минуты
на то, чтобы попасть на машину.

Данные `/var/lib/kandev`, снимок базы вместе с ключом шифрования —
каждую ночь в `/var/lib/kandev/data/backups/`. Версия закреплена в
`servers.yml` (`kandev_version`): миграции необратимы, `latest` не ставим.

</details>

<details>
<summary><b>Agent of Empires</b> — чат с агентом, порт 8065</summary>

New session → папка `projects` первой строкой → репозиторий → Use this
folder → Launch. Агент по умолчанию — первый из `dev_agent_clis`. Сессия
живёт в tmux: закрыл вкладку — продолжишь с того же места.

В терминале то же самое: `aoe`.

</details>

<details>
<summary><b>VS Code</b> — code-server, порт 8063</summary>

Открывается в `/projects`. Расширения и настройки хранятся в
`~/.local/share/code-server`. На телефоне тесен — там удобнее Терминал
и Файлы.

</details>

<details>
<summary><b>Терминал</b> — dinotty, порт 8066</summary>

Открывается в `/projects`. Полные права: `sudo` без пароля. Сессии живут
на сервере и переживают закрытие вкладки — вернулся и продолжил.

С телефона: **добавить страницу на домашний экран**. Дальше она открывается
как приложение, во весь экран, и внизу появляется ряд клавиш, которых нет
на экранной клавиатуре, — `Ctrl`, `Esc`, `Tab`, стрелки. Ради этого он здесь
и стоит: до него был ttyd, и с телефона в нём нельзя было ни прервать
команду, ни выйти из `vim`, ни пройтись по истории.

Раньше терминал держал общую tmux-сессию `console`. Здесь сессии свои,
а `console` никуда не делась — если в ней что-то осталось, она
достаётся привычным `tmux attach -t console`.

</details>

<details>
<summary><b>Файлы</b> — File Browser, порт 8067</summary>

Вся машина, ссылка ведёт в `/projects`. Работает под `dev`: видно почти
всё, править — своё; системные файлы — из терминала через `sudo`.

</details>

<details>
<summary><b>Мониторинг</b> — Beszel, порт 8068</summary>

Настройки нет: машина зарегистрирована автоматически. Пороги и уведомления —
Settings в самом Beszel.

</details>

<details>
<summary><b>Лимиты подписок</b> — своя страница, порт 8070</summary>

Сколько израсходовано в текущем пятичасовом окне и за неделю — у Claude,
Codex и планов z.ai, одной страницей и без похода на сайт каждого.

Настраивать обычно нечего: служба читает те же файлы входа, что завели сами
`claude` и `codex`, а ключ плана z.ai берёт из `auth.json` OpenCode, если план
подключён там. Ключ, которого в OpenCode нет, вписывается
в `/var/lib/vps-dev/limits/providers.env` — цифры появятся через минуту.

Клиент на цифры не влияет: Claude Code, Codex и OpenCode — только транспорт,
остаток подписки знает лишь сам поставщик, и `opencode stats` показывает не
его, а токены и стоимость своих сессий. Поэтому новый поставщик — это новый
адаптер в списке `PROVIDERS` внутри `roles/limits/files/vps-dev-limits`.

Цифры Claude приходят из его API и всегда свежие. У Codex своей точки
«сколько осталось» нет: остаток приезжает в ответе на каждый запрос, и CLI
кладёт его в журнал сессии — поэтому на карточке написано, когда цифра
снята. Поставщик без входа или с протухшим токеном гасит только свою
карточку, остальные показываются как ни в чём не бывало.

</details>

<details>
<summary><b>Почта</b> — Mailpit, порт 8069</summary>

Ловушка: письма проектов остаются здесь и наружу не уходят. В проекте:

```
MAIL_HOST=host.docker.internal
MAIL_PORT=1025
```

и в compose у сервиса, который шлёт письма:

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

</details>

<details>
<summary><b>Dozzle</b> — журналы контейнеров, порт 8060</summary>

Все контейнеры машины, только чтение. Настройки нет.

</details>

<details>
<summary><b>DbGate</b> — клиент баз, порт 8061</summary>

Базы проектов портов наружу не открывают: клиент подключён к их
docker-сетям. Новое подключение: host — имя контейнера базы
(`<проект>-db-1`), порт — стандартный для движка, логин и пароль — из
`.env` проекта. К сети проекта, заведённого после последнего прогона,
клиент подключится следующим `apply`.

</details>

## Правила для проектов

- всё в `/projects`, каждый проект — свой каталог и свой git;
- зависимости и службы проекта — только в контейнерах, на хост ничего не ставится;
- порты — из блока проекта (`ports claim`, `ports map`), через переменные
  и с публикацией только на `127.0.0.1`;
- секреты — в `.env`, в git только `.env.example`.

Полностью — [`docs/MACHINE.md`](docs/MACHINE.md).

## Управление

Кнопка и `make` зовут одни и те же команды.

| Режим кнопки / `make` | Что делает |
|---|---|
| `check` | что изменится, ничего не трогает |
| `apply` | применить настройку; повторно — `changed=0` |
| `audit` | снаружи: открытые порты, крепость SSH |
| `watch` | место на диске, службы, брандмауэр |
| `reboot` | перезагрузить и дождаться возвращения |
| `servers`, `ping` | реестр, отвечает ли |

**Обновить сервер**: поправь версию в `servers.yml` или в `defaults`
роли, `apply`. Заплатки Ubuntu ставятся сами; когда нужна перезагрузка,
дашборд скажет.

**Добавить машину**: блок в `servers.yml`, `apply` с ✓ «Первое подключение».

**Отозвать ключ**: убери строку из `base_deploy_ssh_keys`, `apply`.

**Пересозданная машина**: новый `dev_host_fingerprint` в `servers.yml`
(его напечатает прогон), иначе обвязка откажется подключаться.

**Обновить форк**: кнопка `Sync fork` на GitHub (или `git pull upstream
main`). Секреты живут в хранилище GitHub и не трогаются. Твой файл —
только `servers.yml`, исходный репозиторий его не меняет, поэтому
конфликтов не будет. После синхронизации — `apply`.

<details>
<summary>Локальный запуск с ноутбука</summary>

Нужны Docker и Tailscale. Секреты — в `.env` в корне (ключи те же, что
у секретов форка; пароль root — `VPS_DEV_ROOT_PASSWORD_<ИМЯ_МАШИНЫ>`
прописными, дефис → подчёркивание), путь к ключу — `VPS_DEV_SSH_KEY`.

```bash
make new h=dev-1 ip=1.2.3.4            # вписать в реестр, сверить отпечаток, настроить
VPS_DEV_TRUST_NEW_HOST=1 make apply    # первый прогон без make new
make check                             # сухой прогон
make ssh                               # зайти
```

Ansible запускается в контейнере: на ноутбук ничего не ставится.

</details>

## Как устроено

```
servers.yml            реестр машин, ключи, набор агентов, версия Kandev
ansible/site.yml       порядок ролей и почему он такой — читать первым
ansible/roles/         по роли на предмет: base, firewall, dockerd, ports, kandev, aoe…
scripts/               команды, которые зовут Makefile и кнопка
runner/                образ с Ansible, версии закреплены
docs/MACHINE.md        что проект должен знать про машину
```

Безопасность в трёх фразах. Наружу открыт только UDP-порт Tailscale;
публичный SSH закрывается после проверенного входа по частной сети.
Порты контейнеров привязаны к 127.0.0.1 на уровне Docker и дополнительно
закрыты цепочкой `DOCKER-USER`. Все службы слушают loopback и публикуются
в сеть через `tailscale serve` с TLS.

Первый прогон идёт по SSH и ставит на машину Ansible; следующие обвязка
выполняет на самой машине, вывод — в тот же журнал Actions.
