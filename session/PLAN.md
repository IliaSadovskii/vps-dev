# Разработка в одной сессии: пять файлов, два скилла, один сторож

Дата: 2026-09-11, редакция 3. Редакции 1 и 2 — `asides/single-session-plan-v1.md`,
`-v2.md`: там источники (v2 §2.1), правила из orch (v2 §5.4), построчный
разбор `AGENTS.md` listate (v2 §10.2). Это сырьё для скиллов, в план не входит.

Где что лежит в этом репозитории:

```
session/PLAN.md            этот файл
session/sample/            образец пяти файлов на выдуманном приложении «Переговорки»
session/skills/            два скилла; PRINCIPLES.md — что спрашивать, выводить, как делить
                           (из редакций 1–2); asking.md — правила опроса
ansible/roles/session/     ссылки ~/.claude/skills и ~/.agents/skills → session/skills
```

---

## 1. Что должно получиться

Агент в одной сессии, в любом из трёх клиентов (Claude Code, Codex,
OpenCode), с одним и тем же контекстом:

- знает, что за продукт, какой стек, какие правила — владелец не
  проговаривает это каждую сессию;
- **в предложении решения, до кода**, называет задетые заботы каркаса и,
  найдя непостроенный слой, предлагает построить его отдельным PR;
- документация не отстаёт: один сторож на размер и пути, остальное видно
  владельцу в диффе.

Файлы в проекте заводят скиллы, не руки. Образец `session/sample/` задаёт
только форму файлов; что спрашивать, что выводить из кода, на что делить и в
каком порядке идти — `session/skills/PRINCIPLES.md`, собранный из редакций 1–2
(решение владельца 2026-09-11). Сессия любой формы: одна задача,
две, продолжение ветки. Механизм привязан к трём точкам: старт
(`AGENTS.md`), предложение решения (строка в `AGENTS.md`), сдача (CI).

## 2. Решено и не обсуждается

1. Хуков нет. Ни в одном клиенте.
2. Один `AGENTS.md` ≤ 200 строк, без импортов. `CLAUDE.md` — строка
   `@AGENTS.md`. Codex и OpenCode читают `AGENTS.md` сами.
3. Три клиента получают одно и то же. Всё, что умеет один клиент и не умеют
   два других (маски `.claude/rules/`, импорты, хуки), не используется.
   Изменено против редакции 2, где маски для Claude оставляли: одинаковость
   важнее, решение владельца 2026-09-11.
4. Сторож один, в `make lint` и CI. Форма PR — привычка, не проверка.
5. Порог ADR: дороже одного дня переделать.
6. Файлы проекта пишут скиллы. Содержание — по `PRINCIPLES.md`, форма — по
   образцу. Руками — только сам образец.

## 3. Пять файлов и разделы `AGENTS.md`

Спецификация слоёв — `session/skills/FORMAT.md`: пять типов файлов (что
внутри, чего нет, размер, когда читается, образец), четыре класса знания и
куда едет каждый, разделы `AGENTS.md` с порядком и бюджетом, фильтр строки,
форма описания PR, сторож. Скиллы читают его первым; план его не
дублирует. Форма файлов — `sample/`, содержание — `skills/PRINCIPLES.md`.

Правило заведения файла: он отличается от соседей **условием чтения** или
**сроком жизни**. Иначе это раздел.

## 5. Каркас

```
Каркас — решение, которое следующая фича будет вынуждена повторить.
Сделал один раз и больше ни на что не влияет — фича, не каркас.
```

В каркас попадает забота, которая **повторится** (в каждой второй фиче)
**или** дорога в переделке (данные, права, деньги, внешний контракт,
двадцать мест). Сказанное владельцем — записывается без фильтра.

Шесть осей, по потоку работы: поверхность (через что приходит работа) ·
хранение · обработка · выход · сквозное (права, транзакции, время, i18n) ·
проверка (виды тестов).

Строка: `| Забота | Образец | Правило | Проверка |`. Колонки статуса нет:
забота построена, если есть образец. Появился код — дописывается путь,
это единственная правка строки. `—` законно; проверка может быть «ревью».

Правило под таблицей — сам механизм (единственный источник текста —
`sample/AGENTS.md`):

```
Перед кодом, в предложении решения, назови задетые строки каркаса.
Таблица — пол, не потолок: задача задевает слой, границу или абстракцию,
которой в таблице нет и которую повторит следующая фича, — назови её,
предложи строку и, если нужен образец, отдельный PR до фичи.
Забота без образца — сначала поищи в коде; нашёл — впиши путь.
Не нашёл — отдельный PR с образцом, фича после него, даже если фича первая.
Исключение: образцом становится сам экран или действие фичи (список, форма,
подтверждение) — строй в фиче; такой же экран будет главным в продукте —
строй на его уровне, не уверен — спроси до кода.
PR слоя несёт слой и первый настоящий экран, который его применит; экрана
ещё не нужно — слой ждёт фичу, которая его потребует. Витрины не строим.
Путь вписывается тем же PR.
Строка «решить при первой задаче» — вопрос владельцу в предложении, варианты
с ценой, до кода; решили — впиши правило, построили — впиши путь.
Каркас — подсказка, правда — код.
```

Проверка полноты: два-три сценария из `docs/scenarios.md`, один — где
что-то идёт не так, по шагам, называя задетые заботы. Шаг без заботы —
дыра в таблице; забота без шага — подозрительна.

## 6. Три клиента

| | Claude Code | Codex | OpenCode |
|---|---|---|---|
| `AGENTS.md` при старте | через `CLAUDE.md` = `@AGENTS.md` | сам | сам |
| правило области | строка оглавления | то же | то же |
| скиллы | `~/.claude/skills` → `session/skills` | `~/.agents/skills` → `session/skills` | то же |
| сдача | CI | CI | CI |

Клиентского в схеме — две ссылки, их ставит роль `session`. Что не
уравнивается — следует ли модель написанному; это предмет шага 4.

## 7. Два скилла

`SKILL.md` по agentskills.io, ≤ 180 строк каждый (было 150; `docs-skeleton`
вырос по находкам полигона), в `session/skills/<имя>/`.
Каждый первым делом читает `PRINCIPLES.md` (что и как), `asking.md` (как
спрашивать) и нужный файл `../sample/` (форма).

| Скилл | Когда | Вход | Что пишет | Не трогает |
|---|---|---|---|---|
| `docs-base` | любой проект: пустой, с кодом без `AGENTS.md`, с разросшейся документацией | ответы владельца, код, старые `AGENTS.md` и `docs/` | `AGENTS.md` без раздела «каркас», `docs/README.md`, `CLAUDE.md`, ADR из разборов и комментариев, `docs/<тема>.md`, `scripts/check-agents.sh` в `make lint` и CI | каркас, код |
| `docs-skeleton` | после `docs-base`; повторно, когда упёрся | код, `docs/scenarios.md` (заведёт, если нет), ответы владельца | раздел «каркас», сценарии, `docs/rules/<область>.md`, ADR на решения | код: ничего не строит |

`docs-base` не «сгенерируй файл», а «пройди кандидатов и по каждому
реши»: правило — есть ли проверка; строка — знает ли модель сама
(«используйте PSR-12» — выбросить) или только ты («`lang/**/*.php` уезжает
в публичный бандл» — оставить, «(ловушка)»).

Как спрашивать — `session/skills/asking.md`: черновик на исправление,
не опрос; не спрашивать, если ответ в коде; пачками с рекомендацией;
про продукт — рассказ; ответ в файл сразу; повтор начинается со сравнения.

## 8. Сторож

`scripts/check-agents.sh` (образец — `sample/scripts/check-agents.sh`,
`docs-base` копирует его в проект, в `make lint` и CI): `AGENTS.md`
≤ 200 строк; каждый путь в колонке «Образец» таблицы «## Каркас»
существует; пустая таблица — красный. Только эта колонка, без эвристик
по всему файлу. Проверен: на образце красный по восьми путям (кода нет),
на фикстуре с путями зелёный, на listate красный по размеру и по
отсутствию таблицы.

Остальное из редакции 2 (форма PR, порядок тестов, пути по всему `docs/`)
не строится: владелец читает каждый дифф. Вернуться — один и тот же
промах дважды.

## 9. Где сложно и как это обходится

1. **Скилл, который грамотно спрашивает.** Не опрос с нуля, а черновик на
   исправление (`PRINCIPLES.md` §6–7), форма перед глазами (`sample/`).
   Проверяется на listate.
2. **Структура `AGENTS.md`.** Таблица §4 плюс заполненный образец. Раздел,
   который нечем заполнить, выпадает.
3. **Три клиента.** Общий знаменатель (§6). Проверяется одним срезом в
   каждом. Промах — это промах модели, не механизма.

## 11. Не берём

| Что | Почему | Вернуться, если |
|---|---|---|
| хуки | клиенты различаются, ломаются молча, мешают спросить | агент строит мимо каркаса при таблице перед глазами |
| три файла с импортом | импорт понимает только Claude | — |
| маски `.claude/rules/`, вложенные `AGENTS.md` по каталогам | у трёх клиентов три семантики: Claude — при чтении файла и только `CLAUDE.md`, Codex — от корня до cwd при старте, OpenCode — ближайший | агент системно не читает файл из оглавления |
| сторожа формы PR, порядка тестов, путей по `docs/` | владелец читает каждый дифф | один промах дважды |
| OpenSpec, Memory Bank, сервисы памяти | другой слой или другая задача; артефакт уже есть — git, ADR, PR | срез не влезает в один PR |
| `docs/notes/` | план среза — описание PR; разбор — ADR или выброс | — |

Известно и не лечится файлом: строка «ход не заканчивается обещанием»
(v2 §5.4) нарушалась четыре раза за ночь при прямом указании; остаётся
как правило, а CI владелец проверяет сам.
