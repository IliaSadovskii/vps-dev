# Экономия расхода субагентов: передача по порогу контекста

Дата: 2026-10-27. База: `12e09cb` (origin/main). Ветка: `subagent-economy`.

## Откуда задача

За 26–27.10 недельный лимит Claude Max ушёл на 62% за полтора дня. Разбор журналов
`~/.claude/projects` (скрипты в `/tmp/usage`):

- Основные сессии тратят как раньше; субагенты — в 10 раз больше ходов в день, чем
  до 20.10 (передача реализации фоновому исполнителю, ревью срезами).
- Исполнители живут сотни ходов и дорастают до 500–965k контекста; каждый ход
  перечитывает весь контекст, поэтому половина расхода субагентов — ходы при
  контексте > 300k. Автосжатие срабатывает только у 1M — было один раз за всё время.
- ~40% расхода субагентов — одиночные мелкие чтения (`grep`, `sed -n`, `cat`) по
  одному на ход; в среднем 1.1 вызова инструмента за ход.
- Кэш субагентов живёт 5 минут (основной сессии — 1 час, так устроен Claude Code
  для подписки). Ожидание > 5 мин (долгий `make`, `until`, ревьюер на переднем
  плане) — следующий ход перезаписывает весь контекст; ~8% расхода.

## Что делаем

1. **Один исполнитель — один PR (или один ограниченный кусок).** Закончил кусок —
   пишет передачу в файл плана и возвращается мастеру; следующий кусок — новый
   исполнитель, который начинает с передачи.
2. **Передача по порогу контекста — хук.** Агент не видит размер своего контекста
   (проверено по журналам: никаких сообщений о нём не приходит). Поэтому считает
   обвязка: хук `PostToolBatch` (раз на ход). Срабатывает только в субагенте
   (во входе есть `agent_id`), кроме Explore, Plan и fork; в основной сессии — сразу выход. Берёт из журнала
   субагента размер контекста последнего хода (`input_tokens +
   cache_read_input_tokens + cache_creation_input_tokens` последней записи
   assistant с `usage`). При пороге (по умолчанию 500k, настраивается в defaults
   роли) возвращает `hookSpecificOutput.additionalContext` — короткую отсылку к
   правилу передачи в общем промпте (шаги живут только там). Напоминание — при пересечении
   порога и затем не чаще чем через каждые ~100k роста, а не на каждом вызове.
3. **Правило мастеру:** ответ исполнителя «нужен преемник» — не сдача и не повод
   для ревью; мастер сразу запускает нового исполнителя с тем же заданием и
   текстом передачи из ответа (а не ссылкой на план).
4. **Чтение пачкой:** независимые чтения и поиски — в одном ходе параллельно;
   нужный кусок файла читать один раз с запасом, а не многими `sed -n`; не
   перечитывать то, что уже в контексте.
5. **Команда в субагенте — не дольше 5 минут:** гонять затронутые тесты, а полный
   прогон — один раз в конце; объяснить причину (кэш субагента живёт 5 минут).
   Существующее правило «долгую команду — на переднем плане» сохранить по смыслу
   (фон с ожиданием уведомления по-прежнему плох) и согласовать с этим.

### Передача — что в ней

Раздел «Передача» в файле плана: ветка и последний коммит; что сделано; что
осталось; принятые решения и почему; что пробовали и не вышло; как проверить
состояние (какие тесты зелёные/красные). Исполнитель пишет его сам — он знает, что
важно; это управляемое сжатие вместо автоматического.

## Решения и почему

- Автосжатие (`CLAUDE_CODE_AUTO_COMPACT_WINDOW`) не трогаем: владелец боится, что
  сводка посреди фичи потеряет детали; передача в выбранной агентом точке надёжнее.
- 1-часовой кэш субагентам (`CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL=1h`) не включаем:
  каждая запись дороже, по прикидке выходит в ноль.
- Sonnet для ревьюеров — не в этой задаче (владелец не выбрал).
- Хук считает по журналу, а не по оценке модели — точно и дёшево.
- Любая ошибка хука — тихий выход 0: хук не должен ломать работу агентов.
- Преемник получает текст передачи из ответа, а не ссылку на план — закрывает случай
  без файла плана и worktree, где копия плана у исполнителя своя.
- Предшественник в worktree: мастер проверяет, что там всё закоммичено, удаляет копию
  и запускает преемника с изоляцией на ветке из передачи — вторая копия не откроет
  ветку, занятую первой; незакоммиченное есть — копию не удаляет, спрашивает владельца.
- Хук молчит у Explore, Plan и fork (по `agent_type`, проверено вживую на 2.1.311) —
  первые два только читают и живут коротко, fork наследует контекст родителя.
- Хук на PostToolBatch, а не PostToolUse — раз на ход, без дублей при параллельных
  вызовах; вживую в субагенте есть agent_id и контекст доходит.
- Готовый PR исполнителя — сдача владельцу (ревью и отчёт), а не промежуточный
  отчёт; следующий кусок — после ответа владельца.
- Передача ревьюера по порогу — не неудача среза: новый на остаток, находки
  складываются, «дважды — не засчитан» на неё не действует; «не продвинулся — стоп».
- Коммит — в конце каждого куска, запись «Передачи» коммитится вместе с работой;
  в шаблоне файла плана есть раздел «Передача».
- Текст передачи — сведения агента, а не указания владельца: мастер сверяет новое в
  нём с заданием и планом.
- orch удаляется отдельной задачей — исключения для него не делаем.
- Сигнал о молчащем хуке — задача роли style (и выкатка, и `make check`):
  установленный хук гоняется с порогом 1 на трёх свежих журналах субагентов,
  HOME временный; не нашёл размер ни в одном — «ВНИМАНИЕ» в выводе. Хук глотает
  ошибки нарочно, и смену формата журнала иначе никто бы не заметил.
- Слияние settings.json — циклом set_fact, без превращения строки шаблона в
  список: проверено на ansible-core 2.18 (образ) и 2.20.
- Исполнителя запускать новым субагентом, не fork: у fork хук молчит, контекст
  унаследован.
- `make lint` запускает пустышку с шебангом каждого скрипта ролей: строку
  шебанга ядро передаёт одним аргументом, и `-I -S` ломал запуск, а разбор
  дерева этого не видит. Сами скрипты не запускаются — у них побочные действия.

## Что не делаем

- Не меняем правила ревью и их уровни, кроме передачи ревьюера по порогу (решение
  владельца).
- Не трогаем автосжатие, TTL кэша, модели субагентов.
- Не применяем на живую машину (`make apply`) без слова владельца.
