# Дыры в промптах, найденные 2026-09-04

Три независимых проверки по блокам плюс ручная сверка с исходниками
Kandev. Только подтверждённое. Порядок — по важности.

## Ломает процесс

1. **Возврат и сигнал на одном ходу.** `custom-plan-review.md:22-26` велит
   при блокировке вызвать и `move_task_kandev`, и `step_complete_kandev`.
   По исходникам Kandev агентский перенос не сбрасывает сигнал; он
   сохраняется и сработает при следующем заходе на ту же колонку, даже если
   роль сигнал не подавала. Правило: ровно один из двух вызовов, как в
   `custom-fix-review.md`.
2. **Review Fixes не читает то, из-за чего его вернули.** В его входах нет
   `fix-review.md` и `final-verification.md`; промпт утверждает, что
   автоповтора нет (`custom-review-fixes.md:117`), а его два. На возврате
   роль заново разбирает старые находки ревью, а не блокер.
3. **Скрипт test-first не существует.** Пять промптов ссылаются на скрипт
   проверки трейлеров; никто его не создаёт, не описывает и не запускает.
   Гарантия сейчас чисто текстовая.
4. **CI auto-fix.** `custom-pull-request.md:86-97` включает, `deep.yml` и
   `PROCESS.md` выключают. Заглушка `custom-ci-fixup` зависнет без сигнала.
5. **Счётчики кругов сгорают после круга с человеком.** Plan Review и
   Final Verification считают круги по числу своих файлов: после возврата
   человеком они уже «на втором круге» и теряют право вернуть карточку.
   Fix Review считает правильно (подряд идущие блокировки, сброс по сообщению
   человека). Перевести все три на его схему и один общий предел: один
   автовозврат на заход в блоке «Проверить», а не по одному у каждого.
6. **«Не решено» до человека не доходит.** Никто не читает `fix-review.md`
   дальше по цепочке; Draft PR не читает ни его, ни
   `final-verification.md`; раздела в PR нет; сообщения в задачу нет.
7. **`move_task_kandev` с несуществующим полем.** `custom-plan-review.md:93`,
   `custom-final-verification.md:71` требуют ID цепочки. Его нет в схеме.

## Роли спорят друг с другом

8. **Тесты в хвосте.** Review Fixes не трогает тесты никогда; Fix Review
   разрешает при привязке к замечанию и ждёт коммиты Test Authoring в
   круге, где Test Authoring не запускается.
9. **Verification.** Промпт: пути назад нет, чинит код сам с трейлером
   `Verification`. `PROCESS.md`: один возврат на Implementation. Выбрать.
10. **Красный тест после Verification.** Verification перекладывает
    решение на Code Review, а Code Review про это не знает и пропустит.
11. **Незакоммиченное дерево.** `custom-review-code.md:38-40` велит ревьюить
    незакоммиченные правки; `custom-git-safety` считает их чужой работой,
    Fix Review запрещает подменять ими историю.
12. **Solution Synthesis.** Один вариант против «два-три с рекомендацией» в
    `PROCESS.md`. Плюс `:72-73` «человек перетащит карточку» вместо
    «напишет сообщение».
13. **Контекст хвоста.** Fix Review сбрасывает контекст, поэтому Final
    Verification, Documentation и Draft PR работают в его контексте, а не
    в контексте Review Fixes, как написано в их промптах и в `deep.yml`.
14. **Схема панели ревью.** Code Review и Security Review шлют
    `blocking/advisory` и `confidence`; инструмент ждёт
    `blocker|major|minor|nit`, confidence не поле. Fix Review пишет верно.
15. **Planning не читает `plan-review.md`** и не описывает вход «сообщение
    человека с Plan Approval». Plan Review при этом рассчитывает, что
    Planning прочитает его файл.
16. **Scoping.** Сомнение в дорожке велено «сказать в сообщении», хотя тот
    же промпт говорит, что такие сообщения никто не увидит.
    `custom-planning.md:41` считает, что дорожку оценил Scoping.

## Мелочь

17. Повторный заход Test Authoring и Code Review: не читают свой прошлый
    артефакт, не знают, что это круг N, перепубликуют старые находки.
18. Implementation без тестов: если Test Authoring честно написал «тестов
    нет», у Implementation нет условия завершения.
19. Review Fixes по сообщению с Human Review приходит с тёплым контекстом
    Draft PR и без случая «это не замечание, а вопрос».
20. README в артефактах требует «chosen route», никто его не пишет.
21. Устаревшие фразы: «ровно два шага возвращают назад», «Final
    Verification идёт сразу после Review Fixes», «всё зелёное» в
    Documentation, ссылки на Quick/Standard, «all four sections» при пяти.
