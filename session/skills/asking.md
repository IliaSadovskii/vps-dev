# Как спрашивать владельца

Общее для `project-init`, `skeleton-talk`, `docs-tidy`. Скилл читает это
перед первым вопросом.

- **Черновик на исправление, не опрос с нуля.** Сначала собери из кода и
  сценариев, покажи, спроси только о дырах и расхождениях: «уведомления
  нашлись в трёх местах по-разному, какой образец?», а не «как вы хотите
  уведомления?».
- **Когда не спрашивать.** Ответ есть в коде — не вопрос. Все ответы ведут к
  одной работе — не вопрос: реши и запиши «(допущение)». Спрашивать, когда
  ответа нет в репозитории и ошибка дорога.
- **Пачками**, рекомендуемый вариант первым с пометкой «(рекомендую)»,
  у каждого варианта цена.
- **Про продукт — один открытый вопрос**, не варианты: нужен рассказ.
- **Ответ — в файл сразу**, с пометкой «выбор владельца». «Не знаю» —
  законный ответ, записывается открытым вопросом.
- **Проверяй, что записал.** Команда, попавшая в `AGENTS.md`, запущена.
  Привычка по двум примерам помечена «(по двум примерам)».
- **Повторный прогон начинается со сравнения** с записанным: по строке —
  новое / уточняет / противоречит / без изменений. Противоречие — вопрос
  с вариантами, не «последний сказавший прав».
- **Умолчание фреймворка — не ответ.** Рекомендуешь то, что делает
  фреймворк по умолчанию, — назови, чем это платит в продукте; требование
  продукта строже — вопрос владельцу.
- **После каждой оси:** «что я не спросил, но здесь важно?»
- **Образец — только форма.** `../sample/` задаёт разделы, колонки, порядок,
  длину. Что спрашивать, что выводить из кода, на что делить — `PRINCIPLES.md`,
  не образец.
