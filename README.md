# vps-dev

Превращает чистую Ubuntu в **сервер разработки, где работают агенты**.

Форкнул, положил секреты, нажал кнопку — получил ссылку в своей частной сети
на доску, где задачи ведут агенты, а ты читаешь результат и жмёшь «годится».

Ни один провайдер не зашит: Claude Code, Codex, Gemini CLI, OpenCode — что
перечислил в реестре, то и встанет. Разговаривает с ними
[Kandev](https://github.com/kdlbs/kandev), а не наша обвязка.

## Что получается

| | |
|---|---|
| **Доска** | Kandev: задача едет по шагам, на каждом свой агент со своим промптом |
| **Чат** | Agent of Empires: поговорить с агентом в терминале или из браузера |
| **Проекты** | `/projects`, docker, блоки портов, общий прокси, дашборд со ссылками |
| **Наружу** | ничего. Ни 80, ни 443, ни 22. Единственный вход — Tailscale |

## Установка

Нужна чистая **Ubuntu 24.04** и SSH-ключ у root.

1. Форкни этот репозиторий и включи в форке Actions.
2. Положи в секреты форка (Settings → Secrets and variables → Actions):

   | Секрет | Что это |
   |---|---|
   | `SSH_PRIVATE_KEY` | закрытый SSH-ключ; открытая половина — в `servers.yml` и у root новой машины |
   | `TAILSCALE_OAUTH_CLIENT_ID`, `TAILSCALE_OAUTH_SECRET` | клиент OAuth с тегом `tag:ci`: им раннер входит в сеть на время прогона |
   | `TAILSCALE_OAUTH_SERVER_CLIENT_ID`, `TAILSCALE_OAUTH_SERVER_SECRET` | клиент OAuth с тегом `tag:server` и правом `auth_keys` на запись: им машине выпускается ключ на один прогон |
   | `VPS_DEV_ROOT_PASSWORD` | пароль root для веб-консоли провайдера |
   | `VPS_DEV_NTFY_TOPIC` | имя топика уведомлений, любая строка |

   В ACL Tailscale должны быть объявлены `tag:ci` и `tag:server`, `tag:ci`
   и твои устройства должны иметь доступ к `tag:server`. В Settings → DNS
   нужны MagicDNS и HTTPS Certificates: без них не поднимется дашборд.
3. Actions → «Сервер разработки» → Run workflow: адрес машины, режим `apply`.
4. Зайди на машину и один раз войди в каждый CLI агентов — браузером.

Четвёртый шаг автоматизировать нельзя: свой вход в чужом коде запрещён
условиями всех провайдеров. Всё остальное делает кнопка.

## Команды

Те же цели `make`, что зовёт кнопка, — разойтись они не могут.

| Команда | Что делает |
|---|---|
| `make apply` | Применить настройку |
| `make check` | Показать, что изменится. Ничего не трогает, заодно проверяет код |
| `make audit` | Проверить снаружи: отвечает ли что-нибудь, крепок ли SSH |
| `make watch` | Присмотр: место на диске, службы |
| `make servers` | Показать реестр машин |
| `make new h=имя ip=адрес` | Завести машину |
| `make ssh` | Зайти на сервер |

Ansible запускается в контейнере: на твоей машине ничего не ставится,
а версия инструмента одинакова у всех.

## Устройство

```
servers.yml          реестр машин и настройки: чьи ключи, какие CLI, версия Kandev
ansible/site.yml     порядок ролей — там же объяснено, почему именно такой
ansible/roles/       по роли на предмет
runner/              образ с Ansible, версии закреплены отпечатками
scripts/             то, что зовёт Makefile
docs/                контракт проекта: как устроен проект, чтобы агент его поднял
```

## Чем это не является

Не боевой сервер. Здесь нет ни доменов, ни сертификатов, ни Cloudflare —
машина закрыта целиком, и открывать её нечем и незачем.

Не замена агенту: оркестрацией занимается Kandev, обвязка только ставит
и охраняет машину.
