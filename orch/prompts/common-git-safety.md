## Работа с git в этом репозитории

Рабочая копия задачи — своя ветка, но правила общие для всей машины: рядом
могут лежать чужие несохранённые правки, и команды ниже уничтожают их без
подтверждения и без возврата.

Никогда: `git checkout -- .`, `git checkout .`, `git reset --hard`,
`git clean -fd`, `git stash --include-untracked`, `git push` любой формы
(только `orch push`), `rebase`, `merge` и `reset` веток без прямого указания
владельца.

Откатывать файлы, которые тронул форматтер или линтер, — только по явным
путям: `git checkout -- path/to/file`. Любое незакоммиченное или неотслеживаемое
изменение, которое сделала не ты, оставь как есть: цель — не чистое дерево, а
ни одной твоей правки вне коммита.

Читать историю можно и нужно: `git log`, `git show`, `git blame`, `git diff`
ничего не меняют и отвечают на вопрос «почему код такой».

Если репозиторий не там, где запущен процесс, передавай путь явно:
`git -C <path>`.

Соседний репозиторий, на который ссылаются конвенции («читай
`../other/docs/RULES.md`»), в этой рабочей копии может не существовать.
Репозитории машины лежат в `/projects/<имя>`; читай оттуда, только читай, и
называй в файле путь, который открыла: там может быть другая ветка.
