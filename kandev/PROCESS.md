# Как вести задачу по цепочке

Перед первой задачей на Deep прогоните цепочку Conventions: она заведёт
или обновит `AGENTS.md` проекта, который все роли читают первым.

Есть что рассказать о продукте — кто им пользуется, что он должен
делать, чем заканчиваются истории — надиктуйте это в карточку на
цепочке Blueprint. Роль покажет, что рассказ меняет в уже записанном,
спросит одним пакетом только о противоречиях и концовках сценариев,
разложит остальное по `docs/knowledge/` и перечислит, что решила за вас.
Разложенное сначала сверяет с рассказом Blueprint Review, потом на
Human Review читаете его и список «решил за вас»: вправо — принять,
заметки и назад на Blueprint — поправить. Без этого описания Deep
работает как прежде; с ним роли читают его наравне с `AGENTS.md`.

У обеих служебных цепочек между работой и человеком стоит машинная
сверка — `Conventions Review` и `Blueprint Review`: она открывает то, на
что ссылается написанное, и возвращает карточку автору, если написанное
расходится с репозиторием. Возврат один между вашими сообщениями, дальше
остаток идёт к вам строкой «Не решено:».

Обе служебные цепочки коммитят на ветку своей задачи. Deep ветвится от
main и увидит `AGENTS.md` и `docs/knowledge/` только после слияния:
слейте PR служебной цепочки (без remote — ветку локально) до первой
задачи Deep по этому проекту.

## Правила

1. **Вы решаете в четырёх местах:** запуск, ответы на вопросы агентов,
   утверждение решения и плана, приёмка. Остальное едет само.

2. **Ворота — колонки, где карточка ждёт вас.** Агент там сам пишет, что
   сделано и что решить, а потом задаёт один вопрос, варианты которого — это
   исходы: у каждого сказано, куда после него поедет карточка. Отдельного
   «куда двигать» нет — это то же решение, спрошенное дважды. Файлы открывать
   не нужно: всё, чтобы решить, он выносит в сообщение.

3. **Всё сказанное на воротах — это письмо следующему шагу.** Отвечайте как
   удобно: нажатием на вариант или словами, одним сообщением или пятью, хоть
   через час. Можно спорить и переспрашивать — агент читает файлы предыдущей
   роли и отвечает по ним. Каждый его ответ заканчивается списком того, что
   записано, **и для кого**. Список стал таким, какой нужен, — можно тащить.
   Говорить «готово» не надо.

   Адресата видно всегда, и меняется он обычными словами: «это для
   планирования», «верните на тесты». С `Human Review` выходов семь, там это
   особенно нужно; на остальных воротах адресат один и меняется редко.

4. **Вправо — принимаю, назад — переделать.** Любой из предложенных
   вариантов, даже не рекомендованный, это «принимаю»: назад тащат, когда
   не подходит ни один. Заметки пишите до перетаскивания — перетаскивание
   запускает агента сразу.

5. **Агент возвращает работу назад сам** только на шаг и только раз за
   заход. Дальше приходит к вам с пометкой «Не решено».

## Цепочка

```text
 Понять        Backlog → Discovery → Scoping
 Выбрать       Research → Solution Synthesis → [Solution Approval]
 Спланировать  Planning ⇄ Plan Review → [Plan Approval]
 Сделать       Test Authoring → Implementation ⇄ Verification
 Проверить     Code Review → Review Fixes → Fix Review
               → Final Verification → Draft PR
 Принять       [Human Review] → Done
```

`[ ]` — ворота, карточка ждёт вас. `⇄` — агент может один раз вернуть.
Ещё два возврата: Fix Review и Final Verification возвращают на Review
Fixes, один раз на заход вместе. И два прыжка вперёд, когда вход пуст:
Research без развилок едет сразу на Planning (Solution Approval вы не
увидите), Code Review без находок у обоих чтений едет сразу на Final
Verification.

## Ваши действия

| Где | Что делать |
|---|---|
| Backlog | Дописать условие. Перетащить на Discovery |
| Висит вопрос агента | Ответить в карточке. Не перетаскивать |
| Solution Approval | Выбрать вариант. Вправо, или замечания и назад |
| Plan Approval | Принять план. Вправо, или поправить План в интерфейсе и вправо, или замечания и назад |
| Human Review | Дождаться CI, посмотреть diff. В Done, или замечания и назад |
| Done | Переоткрыть — замечания и назад на Review Fixes |
| Все остальные колонки | Ничего |

Записку агента на воротах достаточно прочитать в карточке. Открывать файлы,
панель ревью и описание PR стоит тогда, когда хотите проверить сами, а не
чтобы понять, что решать.

## Куда тащить назад

Вариант из предложенного списка — это принятие, а не возражение: любой из
них, включая не рекомендованный, едет **вперёд**. Назад — когда ни один не
подходит: «Другое», замечания, другое направление.

| Что не так | Куда |
|---|---|
| Ни один из вариантов не подходит (с Solution Approval) | Solution Synthesis |
| Нужны новые данные по вариантам | Research |
| План, задача та же | Planning, потом снова Plan Review |
| Ошибка в коде, замечание к реализации, упавший CI | Review Fixes, потом весь хвост до PR |
| Нужен новый или другой тест | Test Authoring |
| Задача поменялась | Scoping |
| Не так оформлен PR | Draft PR |

Перетащить руками можно только в эти колонки, в Discovery из Backlog и в
Done с Human Review; остальные колонки закрыты для перетаскивания, туда
карточка попадает сама. Заметки пишите до перетаскивания: перетаскивание
запускает агента сразу.

## Карточка застряла

Агент не работает, карточка не едет.

1. Посмотреть, не ждёт ли агент вас: висящий вопрос или запрос разрешения
   на команду. Ответить. Если запросы разрешений повторяются, у профиля
   агента выключено автоодобрение — включить в настройках Kandev до
   запуска, иначе каждая команда будет ждать вас.
2. Прочитать последнее сообщение агента.
3. Написать «продолжай»: агент продолжит с той же памятью.
4. Нужен перезапуск — нажать Stop, написать заметку «перезапусти» с
   причиной, перетащить в Backlog, потом на первую колонку блока
   (Discovery, Research, Planning, Test Authoring, Review Fixes, Draft
   PR): блок пройдёт заново. Без заметки роль остановится и спросит, зачем
   её вернули. Память очистится на колонках со сбросом, остальные
   продолжат с прежней.

Случайно утащили готовую карточку из Done в рабочую колонку: роль увидит,
что заметки нет, спросит одной строкой и встанет. Перетащите обратно в
Done.

## Что за этим стоит

Решения — в `research/DECISIONS.md`, отчёт о пробном прогоне — в
`research/TRIAL-2026-09-04.md`. Quick и Standard — после первых
настоящих задач на Deep.
