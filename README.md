# vps-dev

Превращает чистую Ubuntu в **сервер разработки, где работают агенты**.

Форкнул, положил секреты, нажал кнопку — получил ссылку в своей частной сети
на доску, где задачи ведут агенты, а ты читаешь результат и жмёшь «годится».

Ни один провайдер не зашит: Claude Code, Codex, Gemini CLI, OpenCode — что
перечислил в реестре, то и встанет. Разговаривает с ними
[Kandev](https://github.com/kdlbs/kandev), а не наша обвязка.

## Что получается

| | |
|---|---|
| **Доска** | Kandev: задача едет по шагам, на каждом свой агент со своим промптом |
| **Чат** | Agent of Empires: поговорить с агентом в терминале или из браузера |
| **Проекты** | `/projects`, docker, блоки портов, общий прокси, дашборд со ссылками |
| **С браузера** | терминал в `/projects`, файлы проектов, журналы, клиент баз |
| **Наружу** | ничего. Ни 80, ни 443, ни 22. Единственный вход — Tailscale |

## Установка

Нужна чистая **Ubuntu 24.04** и SSH-ключ у root.

1. Форкни этот репозиторий и включи в форке Actions.
2. Положи в секреты форка (Settings → Secrets and variables → Actions):

   | Секрет | Что это |
   |---|---|
   | `SSH_PRIVATE_KEY` | закрытый SSH-ключ; открытая половина — в `servers.yml` и у root новой машины |
   | `TAILSCALE_OAUTH_CLIENT_ID`, `TAILSCALE_OAUTH_SECRET` | клиент OAuth с тегом `tag:ci`: им раннер входит в сеть на время прогона |
   | `TAILSCALE_OAUTH_SERVER_CLIENT_ID`, `TAILSCALE_OAUTH_SERVER_SECRET` | клиент OAuth с тегом `tag:server` и правом `auth_keys` на запись: им машине выпускается ключ на один прогон |
   | `VPS_DEV_ROOT_PASSWORD` | пароль root для веб-консоли провайдера |
   | `VPS_DEV_NTFY_TOPIC` | топик на ntfy.sh, куда машина шлёт уведомления. Длинная случайная строка: на публичном сервере имя топика — это пароль |

   В ACL Tailscale должны быть объявлены `tag:ci` и `tag:server`, `tag:ci`
   и твои устройства должны иметь доступ к `tag:server`. В Settings → DNS
   нужны MagicDNS и HTTPS Certificates: без них не поднимется дашборд.
3. Actions → «Сервер разработки» → Run workflow: адрес машины, режим `apply`.
4. Открой главную страницу машины в своей сети, зайди в терминал и один раз
   войди в каждый CLI агентов — браузером (см. «Как пользоваться»).

Четвёртый шаг автоматизировать нельзя: свой вход в чужом коде запрещён
условиями всех провайдеров. Всё остальное делает кнопка.

## Как пользоваться

Всё живёт за Tailscale. Единственная закладка — главная страница машины:
`https://<имя-машины>.<твоя-сеть>.ts.net/` (или просто имя без схемы). На ней
ссылки на всё, что крутится, и предупреждение, если машина просит перезагрузки.

| Порт | Что | Зачем |
|---|---|---|
| 8064 | **Kandev** | доска: задача едет по шагам, на каждом свой агент |
| 8065 | **Agent of Empires** | поговорить с агентом в браузере; сессии живут в tmux |
| 8066 | **Терминал** | консоль в `/projects`: клонировать, войти в CLI агента, `ports map` |
| 8067 | **Файлы** | файлы проектов: посмотреть, скачать, загрузить |
| 8060 | Dozzle | журналы контейнеров |
| 8061 | DbGate | клиент баз данных проектов |
| 80xx | проекты | каждый веб-сервис проекта — на своём порту из его блока |

Пароля нигде нет: границу держит Tailscale. Кто в твоей сети — тот и хозяин
машины, поэтому не пускай в сеть чужих.

### 1. Войти в CLI агентов — один раз, руками

Открой терминал с главной страницы (или `make ssh`) и войди в каждого
провайдера из `dev_agent_clis`:

```
claude auth login
codex          # в меню — Sign in with ChatGPT
gemini         # в меню — Sign in with Google
opencode auth login
```

Вход браузером: команда напечатает ссылку, открой её, подтверди. Логин
общий для Kandev, Agent of Empires и терминала — все три работают под одним
пользователем `dev`, поэтому входить достаточно один раз.

### 2. Положить проекты

Все проекты — в `/projects`. Три способа, любой:

- в терминале: `cd /projects && git clone …`;
- в Kandev: репозиторий → «Клонировать по URL» (кладёт туда же);
- с ноутбука: `scp`/`rsync` через `make ssh`-адрес или через «Файлы».

Каждому проекту — блок из 10 портов: в терминале `ports claim <имя>`, карта —
`ports map`. Как проект должен быть устроен, чтобы агент его поднял без
вопросов, — `docs/PROJECT-CONTRACT.md`; агенту можно дать задание из конца
того файла.

### 3. Kandev

Открой доску. Репозитории из `/projects` она находит сама (глубина 3);
CLI агентов видит те, что установлены на машине, — если чего-то нет,
нажми Rescan. Дальше по порядку: репозиторий и базовая ветка → профиль
агента (executor **Worktree** — отдельная копия под каждую задачу, не
трогает твою) → задача. Снимок базы Kandev вместе с ключом шифрования
делается каждую ночь в `/var/lib/kandev/data/backups/`.

### 4. Agent of Empires

«Новая сессия» → выбери папку проекта (обзор начинается с `/projects`) →
агент по умолчанию — первый из `dev_agent_clis`. То же самое в терминале:
команда `aoe`.

### 5. Перезагрузка и обновления

Заплатки ставятся сами. Когда машина просит перезагрузки, главная страница
скажет об этом: Actions → «Сервер разработки» → режим `reboot`, либо
`sudo reboot` в терминале. Автоматически не перезагружается никогда.

## Команды

Те же цели `make`, что зовёт кнопка, — разойтись они не могут.

| Команда | Что делает |
|---|---|
| `make apply` | Применить настройку |
| `make check` | Показать, что изменится. Ничего не трогает, заодно проверяет код |
| `make audit` | Проверить снаружи: отвечает ли что-нибудь, крепок ли SSH |
| `make watch` | Присмотр: место на диске, службы |
| `make servers` | Показать реестр машин |
| `make new h=имя ip=адрес` | Завести машину |
| `make ssh` | Зайти на сервер |
| `make reboot` | Перезагрузить и дождаться возвращения |

Ansible запускается в контейнере: на твоей машине ничего не ставится,
а версия инструмента одинакова у всех.

## Устройство

```
servers.yml          реестр машин и настройки: чьи ключи, какие CLI, версия Kandev
ansible/site.yml     порядок ролей — там же объяснено, почему именно такой
ansible/roles/       по роли на предмет
runner/              образ с Ansible, версии закреплены отпечатками
scripts/             то, что зовёт Makefile
docs/                контракт проекта: как устроен проект, чтобы агент его поднял
```

## Чем это не является

Не боевой сервер. Здесь нет ни доменов, ни сертификатов, ни Cloudflare —
машина закрыта целиком, и открывать её нечем и незачем.

Не замена агенту: оркестрацией занимается Kandev, обвязка только ставит
и охраняет машину.
