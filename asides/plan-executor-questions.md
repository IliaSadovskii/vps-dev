# План: исполнитель спрашивает, ревью проверяет результат, промпт по ролям

База: `5b057d8` (origin/main, 2026-11-24). Ветка: `executor-questions`. Проверенная точка: `529de68` (кусок 2, ревью 1 ревьюером + безопасность, 2026-11-24).

## Что делаем и зачем

Инцидент 2026-11-24 (CRM): решение владельца передано исполнителю дословно, исполнитель доложил «сделано, проверено», ревьюер читал только код, мастер сказал «готово» — решение выполнено наполовину и не так, как имел в виду владелец. Причины: исполнитель сам решал то, что задаёт владелец; нет канала «спросить мастера»; одно решение вмещало несколько требований; результат проверял только исполнитель; дополнения сообщением посреди работы. Заодно — аудит остальных промптов (2026-11-24, Fable): противоречия, устаревшее, общий промпт написан для трёх ролей сразу и грузится каждому субагенту.

«Готово»: правила выкатываются (`make check` без ошибок), каждая роль (мастер, исполнитель, ревьюер) получает только своё; находки аудита закрыты или отклонены с причиной; ревью кусков и разбор устройства пройдены.

## Решения

- Р1. Правила общие для любой разработки (бэк, фронт, архитектура), без привязки к случаю; коротко — суть и цель, а не рамки. Решение владельца 2026-11-24. Проверка: ревьюер.
- Р2. Исполнитель сам решает только то, что прямо следует из решений, плана или соседнего кода, и мелочь, которую владелец не увидит и дёшево переделать, — с записью в «выбрал сам»; видимое владельцу и устройство задают решения и владелец, остальное — вопрос мастеру; вопрос — не провал куска. Решение владельца 2026-11-24. Проверка: ревьюер.
- Р3. Мастер — заместитель владельца: отвечает исполнителю сам, только если ответ есть в плане, решениях, документах области или словах владельца, с источником; иначе и при любом отступлении от решения — вопрос владельцу. Решение владельца 2026-11-24. Проверка: ревьюер.
- Р4. Снято владельцем 2026-11-24: правило о решениях — прежним текстом; половинчатое выполнение ловит ревью результата (Р6). Проверка: `prompt-work.md.j2` — пункт о «Решениях» как в базе `5b057d8`.
- Р5. Новых сущностей рядом с «Решениями» не заводить (пункты «готово» и т. п.). Решение владельца 2026-11-24. Проверка: ревьюер.
- Р6. Результат проверяет обычное ревью, одной ролью: первый ревьюер до кода проверяет результат способом области (интерфейс — глазами, API — запросами, данные — на копии); отдельной роли тестировщика нет. Решение владельца 2026-11-24. Проверка: ревьюер.
- Р7. В отчёте владельцу по решениям — только отклонения («нет», «иначе»). Решение владельца 2026-11-24. Проверка: ревьюер.
- Р8. Дополнение к заданию не досылается исполнителю посреди работы: отменяет делаемое — остановить и дать задание заново, иначе — после передачи. Решение владельца 2026-11-24. Проверка: ревьюер.
- Р9. Аудит — одним заходом: противоречия, устаревшее и разделение общего промпта по ролям, чтобы каждая роль грузила только своё. Решение владельца 2026-11-24 (без отдельного сравнения вариантов). Проверка: ревьюер, разбор устройства.
- Р10. Хук «субагент — в фон» (`~/.claude/hooks/agent-background.sh`) — в выкатку роли `style` с актуальным обоснованием; раздел «Как со мной разговаривать» удалён намеренно — заготовку `files/agent-style.md` обнулить, README и defaults поправить. Решение владельца 2026-11-24. Проверка: `make check`, ревьюер.
- Р11. Скиллы агентам — копией при выкатке, а не ссылкой на рабочее дерево клона; Paseo пишет свои скиллы туда же, его скиллы уходят из репозитория; правка скилла действует после `make apply`. Решение владельца 2026-11-24. Проверка: `make check`, ревьюер.
