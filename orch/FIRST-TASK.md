# Первая настоящая задача: авторизация в listate-crm

Прогоняется этапом 4 (`PLAN.md` §10) после `smoke` и Conventions, когда
оркестратор работает и роли гонялись хотя бы на полигоне. Разработчик
оркестратора здесь играет **владельца**: отвечает на вопросы ролей, решает на
воротах, спорит, а в конце сравнивает результат с ожиданиями ниже. Ожидания
ролям не показываются: они — мерило, не условие.

## Проект

`/projects/listate-crm` — Laravel, `AGENTS.md` есть (заведён цепочкой
Conventions в Kandev), `docs/knowledge/` нет. Стек фронта выбран владельцем
ранее: PrimeVue (в задаче он назван «Prime View»). Почта на машине ловится
Mailpit: отправлять на `host.docker.internal:1025` из контейнера, смотреть на
`127.0.0.1:8069` (`/var/lib/vps-dev/style/machine/mail.md`). Задача идёт
цепочкой `deep` с листом по умолчанию.

## Текст задачи (условие, как его продиктовал владелец)

```
Разработать модуль аутентификации и авторизации пользователей.

Вход по социальным сетям, Google и Яндексу не планируется. Нужен обычный
вход по рабочей почте (email) и паролю. Желателен также вход по одноразовому
паролю, который отправляется на рабочую почту.

Регистрации через форму нет: первого пользователя заводит администратор
консольной командой. Остальных пользователей будет заводить этот
пользователь через форму внутри приложения — её в этой задаче тоже не делаем.

Фронт — на выбранном стеке PrimeVue. По максимуму использовать готовые
решения, желательно от Laravel: они надёжнее самописных.
```

## Чего владелец ожидает (мерило для сравнения)

1. На dev-сервере не стартовая страница Laravel, а вход: кнопка «Войти»,
   форма email + пароль.
2. Есть заведённый тестовый пользователь; владельцу выданы его логин и
   пароль, по ним можно войти.
3. Вход по одноразовому коду: код приходит в Mailpit (`127.0.0.1:8069`), по
   нему можно войти.
4. Решение архитектурно правильное, в духе domain-driven design, как
   записано в `AGENTS.md` проекта; не переусложнено.
5. Использован готовый механизм аутентификации Laravel, а не самописный.
6. Фронт аккуратный, визуально не стыдный.
7. Есть тест Playwright, который проходит сценарий входа и подтверждает, что
   визуально всё в порядке.

Общий промпт машины (`/var/lib/vps-dev/style/machine/*.md`, `~/.claude/CLAUDE.md`)
подмешивается в каждую сессию, поэтому про Mailpit, порты и браузер роли
знают без подсказок.

## Как играть владельца

- Вопросы ролей: отвечай из условия и ожиданий, коротко, как ответил бы
  занятой человек; где ожидания молчат — выбирай рекомендуемый вариант и
  фиксируй выбор в отчёте.
- Ворота после Решения: сравни варианты с п. 4–5; если рекомендуют
  самописное — верни с комментарием.
- Ворота после Ревью плана: прочитай план как владелец; хотя бы один раз
  верни с содержательным комментарием, если есть за что (проверяем возврат
  с комментарием); если план хорош, не выдумывай.
- Ворота после PR: проверь п. 1–3 руками через браузер машины и Mailpit,
  п. 6–7 по тесту и скриншоту; п. 4–5 по диффу. Замечания — комментарием и
  возвратом в Правки, не правкой руками.
