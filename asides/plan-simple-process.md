# План: упрощённый процесс разработки

База: `153ff28` (main, 2026-11-11). Ветка: `simple-process`. Проверенная точка: `4419d15` (ревью 1 ревьюером, 2026-11-11).

## Что делаем и зачем

Общий промпт агентов вырос до 17,6 тыс. символов, около 80% — ревью и передачи. По журналам CRM проверки стоили дороже написания кода, петли «ревью → починка → круг», затем «сверка → починка», вопросы владельцу непонятны. Внешние источники 2025–2026 (Anthropic best practices, Hashimoto, Willison, Cognition, OpenAI GPT-5.6, ETH) сходятся: план + механические проверки + один свежий ревьюер, короткие инструкции, обязательное — в хуки. Независимый рецензент на Fable подтвердил с правками; главный урок — нарушение решения снял ведущий при разборе находок, а не пропустил регламент.

## Решения

- Р1. Схема: план с разделом «Решения», арх-тест на решение об устройстве первым коммитом куска, один ревьюер на кусок и PR (корректность, данные, решения), второй — по признакам прав/хуков/выкатки/миграций/зависимостей; разбор устройства перед сдачей PR из кусков или нового модуля; без типов ревью, срезов, кругов и сверки. Решение владельца 2026-11-11. Проверка: ревьюер.
- Р2. Нарушение решения и спор решений — починка или вопрос владельцу при любой серьёзности; находки подтверждает исполнитель починки; низкое — в отчёт без починки; повторного ревью нет без слова владельца; дифф починки — в объёме следующего ревью. Предложено рецензентом, решение владельца 2026-11-11. Проверка: ревьюер.
- Р3. Кусок прошёл проверку — отчёт в три строки и следующий кусок без ожидания, если нет вопросов и нарушений решений; сдача с ожиданием — готовый PR. Решение владельца 2026-11-11. Проверка: ревьюер.
- Р4. Хук на длину сессии ведущего — отдельной задачей после этого PR. Решение владельца 2026-11-11. Проверка: не задето этим PR.

## Что не делаем

- Хуки `guard-decisions`, `context-handoff`, `hook-probe` не меняем.
- Реестр 86 решений в плане CRM — дело сессии CRM.
