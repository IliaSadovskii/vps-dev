### 8. Роль/персона (system prompt) — ГЛАВНАЯ НАХОДКА
R1 README, дословно:
> "Avoid adding a system prompt; all instructions should be contained within
> the user prompt."//
> «Избегайте system prompt; все инструкции должны быть в user prompt.»

Это и есть та самая «необычная» рекомендация из брифа. **Проверка
актуальности:** в текущей документации API (api-docs.deepseek.com) примеры
запросов к reasoning-модели используют обычный `system` message
(`{"role": "system", "content": "You are a helpful assistant"}`) как нечто
рутинное, без предупреждений и без повторения запрета из README R1. Прямого
опровержения тоже нет — страница `guides/reasoning_model` при фетче не
отдаёт текст с явными «за/против» по system prompt (техническое ограничение
краулинга, не подтверждённое отсутствие). Вывод: **правило похоже на
специфичное для генерации R1 (январь 2025) и не воспроизводится в текущих
примерах API** — трактовать как устаревшее/не факт, что применимо к
нынешнему поколению. Явного объяснения «почему» в самом README нет — только
императив без обоснования.

### 9. Примеры (few-shot)
Прямой цитаты «не давайте few-shot» в самом README R1 при фетче не найдено
(там про temperature, `<think>`, формат ответа для математики). Совет «avoid
few-shot for reasoning models, use zero-shot with detailed task description»
идёт по вторичным источникам (Together AI, Helicone), которые ссылаются на
поведение R1-класса моделей в целом, а не цитируют официальный DeepSeek-текст
дословно. Помечаю как **вероятно восходящее к DeepSeek, но не подтверждено
прямой цитатой из официального источника** — держать с пометкой
неуверенности.

### 10. Объём контекста
Не найдено прескриптивных советов, только числа контекстного окна.

### 11. Длинные агентные сессии
Не найдено — нет собственного гайда, см. пункт 6.

### 12. Уникальное
- Принудительное открытие ответа тегом `<think>\n`, чтобы гарантировать, что
  модель вошла в режим рассуждения — техническая рекомендация, аналогов у
  западных провайдеров и у остальных китайских провайдеров в найденном
  материале нет.
- Конкретный числовой диапазон temperature 0.5–0.7 (рекомендовано 0.6) —
  Anthropic такого не предписывает.

## Совпадает с Anthropic
Ничего содержательного не найдено (данных мало).

## Расходится с Anthropic
- «Не используйте system prompt» — прямо противоположно тому, что Anthropic
  и остальная индустрия делают с ролями/системными промптами. Но: похоже,
  это привязано к устаревшей модели (R1, начало 2025) и не подтверждается
  текущими примерами API DeepSeek.

## Уникальное
См. пункт 12 выше (`<think>` префикс, точный диапазон температуры).

# Moonshot / Kimi

## Источники
- https://huggingface.co/moonshotai/Kimi-K2-Thinking — официальная карточка
  модели от Moonshot AI (актуальное поколение, «thinking» агентная модель).
- https://platform.kimi.ai/docs/guide/prompt-best-practice — официальный
  гайд «Best Practices for Prompts» на платформе Kimi API (текущий продукт;
  platform.moonshot.ai редиректит на platform.kimi.ai).
- https://platform.kimi.ai/docs/guide/agent-support.en-US — официальная
  страница про агентную поддержку/tool calls.

## По осям

### 1. Пошаговые сценарии — РАСХОДИТСЯ С ANTHROPIC
Официальный гайд по промптингу прямо рекомендует обратное тому, что сейчас
советует Anthropic:
> "Outline a series of steps for the task. Writing these steps explicitly
> makes it easier for the model to follow"//
> «Распишите задачу как последовательность шагов — так модели легче
> следовать.»
С примером в духе `Step 1 / Step 2`. Это прямая противоположность выводу
Anthropic, что `STEP 1..N` ухудшает качество на задачах с суждением. Правда,
формулировка гайда общая и напоминает старые generic-рекомендации по
промпт-инжинирингу (похожа стилистически на классические гайды OpenAI
конца 2023 — начала 2024), не привязана специально к «thinking»/агентным
моделям — возможно, страница не обновлялась под нынешнее поколение Kimi K2
Thinking / K3.

### 2. Запреты
Не найдено ни за, ни против.

### 3. Нажим и капс (MUST/NEVER)
Не найдено.

### 4. Полнота/точность в ревью
Не найдено.

### 5. Длина вывода — РАСХОДИТСЯ С ANTHROPIC
Гайд прямо советует задавать числовой потолок:
> "Specify the Desired Length of the Model's Output" — модель «is better at
> generating output of a specific number of paragraphs or bullet points»//
> «Указывайте желаемую длину вывода — модель лучше генерирует ответ
> заданного числа абзацев/пунктов.»
Это прямо противоположно выводу Anthropic, что числовые потолки душат
рассуждение. Та же оговорка, что и в п.1: похоже на общий, не
reasoning-специфичный совет из более старого слоя документации.

### 6. Автономность и условие остановки
Официально не найдено ничего (страница agent-support ограничивается
описанием, что модель умеет вызывать инструменты и поддерживает до 200–300
последовательных вызовов — из карточки Kimi-K2-Thinking на HF, не про
условия остановки/обещания вместо действия).

### 7. Описания инструментов
Не найдено специфики глубины описаний — только упоминание стандартного
`tool_choice="auto"`.

### 8. Роль/персона (system prompt)
Карточка модели Kimi-K2-Thinking, официально:
> "You are Kimi, an AI assistant created by Moonshot AI."//
> дефолтный системный промпт, который Moonshot сам прописывает как хороший
> выбор «by default»: "If no special instructions are required, the system
> prompt above is a good default."
Это заметно **расходится не только с Anthropic, но и внутри самой группы
китайских провайдеров** — DeepSeek советует вообще не ставить system prompt,
Moonshot, наоборот, официально рекомендует держать короткий дефолтный.

### 9. Примеры (few-shot)
Умеренная, не радикальная позиция — не «избегайте», а «качество важнее
количества»:
> "Providing examples of general guidance is usually more efficient for the
> model's output than showing all permutations"//
> «Примеры общего назначения обычно эффективнее, чем показ всех вариаций.»
Это не противоречит и не подтверждает жёстко ничью позицию — нейтральный
средний вариант.

### 10. Объём контекста
Специфической рекомендации не найдено.

### 11. Длинные агентные сессии
Официально есть, и это самое конкретное из всей группы провайдеров:
> "Summarize the first few rounds of the conversation" при упирании в лимит
> контекста, плюс возможность «asynchronous» суммаризации всей истории;
> для документов — метод "Chunk and Recursively Build a Complete Summary"
> (последовательная суммаризация по кускам с агрегацией).
Также из другого источника (агрегированные вторичные упоминания, не
процитировано напрямую) — принцип «think in goals, not steps: give
high-level objectives and let the model orchestrate sub-tasks» для
агентных workflow: если это действительно официальная формулировка
platform.moonshot.ai, она **совпадает с духом Anthropic** («не диктуйте
пошагово, доверяйте суждению модели») — но пометка снижена, т.к. я не смог
зафетчить страницу-первоисточник напрямую и цитирую по агрегации поисковика,
а не по прямому тексту страницы.

### 12. Уникальное
- Явные числа temperature под разные режимы: 1.0 для thinking mode, 0.6 для
  instant mode, top_p = 0.95 по умолчанию для обоих — конкретика, которой
  нет у западных провайдеров.
- Поддержка 200–300 последовательных вызовов инструментов как заявленная
  характеристика агентности модели.
- Метод суммаризации документов «chunk and recursively build a complete
  summary» — конкретная техника управления контекстом, которой нет в явном
  виде у остальных провайдеров из этой группы.

## Совпадает с Anthropic
- Управление длинными сессиями через суммаризацию по мере исчерпания
  контекста — общий принцип, тот же дух, что и в современных агентных
  гайдах (хотя Anthropic говорит об этом в других терминах).
- (С пометкой неуверенности) «goals not steps» для агентных workflow.

## Расходится с Anthropic
- Пошаговые `Step 1/Step 2` сценарии — рекомендуют, а не отговаривают.
- Числовой потолок длины вывода — рекомендуют указывать явно, а не избегать.
- Явная персона/роль в system prompt — рекомендуют держать по умолчанию, а
  не считать лишней.

## Уникальное
Температурные режимы под thinking/instant, поддержка сотен последовательных
tool calls, техника «chunk and recursively summarize» для документов.

# Zhipu / GLM

## Источники
- https://docs.z.ai/guides/llm/glm-4.6 — официальный обзор модели.
- https://docs.z.ai/scenario-example/develop-tools/claude,
  https://docs.z.ai/devpack/tool/claude-for-ide,
  https://docs.z.ai/devpack/extension/coding-tool-helper — официальные
  страницы про использование GLM как модели внутри Claude Code и других
  чужих агентных CLI (Codex, OpenCode, Crush, Factory Droid).
- https://github.com/zai-org/GLM-4.5 — официальный репозиторий/model card.

## По осям
По всем 12 осям **отдельного, содержательного гайда по промптингу от Zhipu
для собственного агента/кодовых задач найти не удалось** в пределах бюджета.
Страница про GLM-4.6 ограничивается общими маркетинговыми формулировками
уровня:
> "Natively handles diverse agent tasks with enhanced autonomous planning
> and tool invocation capabilities" / "Excels in task decomposition,
> cross-tool collaboration, and dynamic adjustments"
— то есть описанием возможностей модели, а не рекомендациями по написанию
промптов (это как раз та банальность/маркетинг, которую бриф просил не
записывать содержательно).

### 12. Уникальное — сама стратегия позиционирования
Самое содержательное наблюдение по GLM — не про ось промптинга, а про
стратегию документации: Zhipu **не публикует собственную доктрину
промптинга**, вместо этого официально документирует GLM как
drop-in-замену модели внутри чужих агентных CLI — в первую очередь Claude
Code (через Anthropic-совместимый эндпойнт), а также Codex, OpenCode, Crush,
Factory Droid. Иными словами, для агентного/кодового промптинга Zhipu
фактически отсылает пользователя к промпт-инженерии самого Claude
Code/других инструментов, а не формулирует свою. Это, по сути,
**имплицитное согласие с чужими (в т.ч. Anthropic-овскими) практиками**, а
не расхождение с ними.

## Совпадает с Anthropic
Формально «совпадает», поскольку GLM встраивается в тот же Claude Code и
использует его системные промпты и конвенции без изменений — но это не
собственная рекомендация Zhipu, а следствие архитектуры продукта.

## Расходится с Anthropic
Не найдено ничего содержательного.

## Уникальное
Стратегия «модель как замена под капотом чужого агента» вместо собственного
гайда по агентному промптингу — само по себе интересный контраст с
остальными тремя провайдерами группы, у каждого из которых есть хоть
какой-то собственный текст про промптинг.

# Итог по группе: главный вопрос брифа

**Есть ли рекомендации, прямо противоречащие западным (Anthropic)
провайдерам?**

Да, нашлось два содержательных случая, и оба — с оговорками об актуальности:

1. **DeepSeek (R1, январь 2025):** «не используйте system prompt» — прямая
   противоположность общепринятой практике. Похоже на устаревшее для
   текущего поколения (в актуальных примерах API system prompt используется
   как обычно), явного подтверждения или опровержения в текущих доках
   получить не удалось.
2. **Moonshot/Kimi (текущий официальный гайд platform.kimi.ai):** сразу два
   явных расхождения с текущей позицией Anthropic — рекомендация
   расписывать задачи по шагам (`Step 1/Step 2`) и рекомендация явно
   задавать числовую длину вывода. Это самая надёжно подтверждённая находка
   во всей разведке: цитаты дословные, страница официальная и текущая. Но
   похоже на общий, не reasoning/агентно-специфичный слой документации —
   возможно, не обновлялся вместе с агентными моделями (K2 Thinking/K3).

Плюс внутригрупповое противоречие: DeepSeek говорит «не ставьте system
prompt», Moonshot говорит «ставьте короткий дефолтный system prompt» — то
есть даже внутри китайской группы нет единой позиции.

По Qwen и Zhipu/GLM ничего сопоставимого по конкретности не нашлось —
честный результат: либо гайдов такого уровня детализации у них публично нет,
либо они не проиндексированы/не найдены за отведённый бюджет поисков.
